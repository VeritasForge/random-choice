# 정한 가게를 동료에게 보내기 — 설계 문서

## 1. 한 문단 요약

결과 화면에서 한 곳을 정한 사람이 `보내기`를 눌러 그 가게를 동료에게 보낼 수 있게 합니다.
받은 사람이 링크를 누르면 카카오맵이 아니라 **우리 서비스의 공유 화면**이 열리고, 그 화면에는
음식 종류와 카카오 가게 페이지가 버튼을 누르지 않아도 바로 보이며, 아래에 `나도 뽑아 보기`가
있습니다. 링크에는 가게의 카카오 장소 번호와 우리 음식 종류 식별자만 담습니다.

## 2. 왜 필요한가

검색엔진 정비는 끝났지만, 이 서비스가 실제로 쓰이는 순간은 검색창 앞이 아니라 "점심 직전,
팀 단체 대화방에서 아무도 메뉴를 못 정하는 순간"입니다. 점심은 보통 여럿이 먹으므로, 한 사람이
정한 결과를 동료에게 보내는 순간이 새 사람이 이 서비스를 알게 되는 가장 자연스러운 길입니다.

지금은 그 길이 없습니다. 화면은 주소에 아무 상태도 담지 않아서, 어떤 링크로 들어와도 시작
화면만 열립니다. 정한 가게를 알리려면 사용자가 가게 이름을 직접 쳐서 보내야 하고, 그러면 받은
사람은 우리 서비스를 거치지 않습니다.

첫 대상은 **평일 점심에 동료와 함께 먹는 직장인**입니다(2026-11-25 운영자 결정). 여행 중인
사람은 혼자이거나 한 번 쓰고 마는 경우가 많아 이 기능의 대상으로 삼지 않습니다.

## 3. 목표와 목표가 아닌 것

**목표**

- 한 곳을 정한 직후, 버튼 하나로 그 가게를 다른 사람에게 보낼 수 있다.
- 받은 사람이 링크를 누르면 우리 서비스 화면에 도착하고, 추가로 누르지 않아도 가게 정보를 본다.
- 받은 사람이 `나도 뽑아 보기`로 자기 위치에서 서비스를 써 볼 수 있다.
- 단체 대화방에 뜨는 링크 미리보기의 제목이 "오늘은 돈까스·우동"처럼 종류를 말한다.

**이번에 하지 않는 것**

- 카카오톡 전용 공유(카카오 SDK를 붙이는 방식). 휴대폰의 기본 공유 창으로 충분한지 먼저 봅니다.
- 공유 링크로 들어온 방문을 따로 세는 것. 바로 다음 작업으로 따로 설계합니다(9절).
- 요청 빈도 제한. 2026-11-26에 운영자가 "아직은 걸지 않는다"고 정했습니다. 하루 무료 한도가
  다 차도 요금은 나가지 않고 그날 음식점 찾기만 멈추며, 지금은 사용자가 거의 없어 피해가
  작다는 판단입니다.
- 여럿이 투표해서 정하기, 기록 화면에서 보내기.

**이렇게 되면 실패입니다**

- 받은 사람이 가게 정보를 보려고 버튼을 한 번 더 눌러야 한다.
- 받은 사람의 화면에서 `나도 뽑아 보기`가 스크롤해야만 보인다. 유입이 이 버튼 하나에 달려 있습니다.
- 누군가 주소를 고쳐서 우리 주소 아래에 임의의 글자를 띄울 수 있다.
- 기존 다섯 화면의 동작이 달라진다.

## 4. 확인된 사실과 확인되지 않은 것

**확인된 사실**

- 카카오 가게 페이지(`https://place.map.kakao.com/장소번호`)는 다른 사이트 화면 안에 끼워
  넣어도 정상 표시됩니다. 2026-11-19에 크롬 계열 브라우저에서, 2026-11-26에 **아이폰
  카카오톡의 내장 브라우저**에서 운영자가 직접 확인했습니다. 지금 결과 화면의 가게 창
  (`web/components/PlaceSheet.tsx`)이 이 방식으로 돌고 있습니다.
- 끼워 넣을 때 거는 제한 값은 `web/lib/sheet.ts`의 `SHEET_SANDBOX`입니다. 이 값은 끼워 넣은
  카카오 페이지가 우리 화면 전체를 다른 주소로 보내지 못하게 합니다.
- 카카오 가게 페이지 주소만 통과시키는 검사가 이미 있습니다(`web/lib/visits.ts`의
  `kakaoPlaceUrl`).
- 음식 종류의 이름은 Go 서버만 압니다(`api/internal/cuisine/cuisine.go`의 `rules`). 식별자와
  이름의 짝은 18개입니다. 화면 쪽에는 식별자를 이름으로 바꾸는 표가 없고, 음식점을 찾을 때
  서버가 보내 준 이름을 그대로 그립니다.
- 화면 쪽 시험이 Go 소스를 직접 읽어 두 쪽이 어긋나지 않게 지키는 선례가 있습니다
  (`web/lib/errors.test.ts`가 `handler.go`에서 오류 코드를 뽑아 대조).
- 주소를 복사하는 선례가 있습니다(`web/components/InstallGuide.tsx`의 `copyAddress`).
- 사이트 전체의 링크 미리보기 그림은 `web/app/opengraph-image.png` 한 장입니다.
- 화면 시험은 브라우저 없이 node에서 돕니다. 그래서 이 저장소는 판단을 `web/lib/`에 두고
  `web/app/`과 `web/components/`는 껍데기로 둡니다.

**확인되지 않은 것**

- 안드로이드 카카오톡의 내장 브라우저에서도 가게 페이지가 표시되는지. 표시되지 않을 때를
  위해 `카카오에서 열기` 링크를 항상 둡니다.
- 휴대폰 공유 창에 글과 주소를 함께 넘겼을 때, 카카오톡이 둘 다 받아 주는지. 받는 앱에 따라
  글을 버리고 주소만 남기는 경우가 있다고 알려져 있습니다. 만드는 사람이 실제 기기에서
  확인해야 합니다(7절).
- 공유 화면의 링크 미리보기에 사이트 공통 그림이 그대로 붙는지. 빌드 결과로 확인합니다(7절).

## 5. 검토한 방법과 고른 방법

받은 사람이 링크를 눌렀을 때 무엇을 보게 할지를 먼저 정했고, 그다음 그 화면을 어떻게 만들지를
정했습니다.

**받은 사람이 도착하는 곳**

| 방법 | 장점 | 단점 | 결정 |
|---|---|---|---|
| 카카오맵의 가게 페이지 주소를 보낸다 | 가장 간단하다 | 받은 사람이 우리 서비스에 오지 않는다. 유입이 없다 | 버림 |
| 우리 시작 화면 주소를 보낸다 | 간단하고 유입이 생긴다 | 받은 사람이 가게 정보를 볼 수 없다 | 버림 |
| 우리 서비스의 공유 전용 화면을 보낸다 | 가게 정보를 보면서 우리 서비스도 접한다 | 새 화면이 필요하다 | **선택** (운영자) |

**공유 화면을 만드는 방법**

| 방법 | 장점 | 단점 | 결정 |
|---|---|---|---|
| 별도 주소에 가게만 보여 준다 (`/s/장소번호`) | 가장 작다. 링크에 장소 번호만 담는다 | 화면에 음식 종류가 없다 | 버림 |
| 별도 주소에 음식 종류도 보여 준다 (`/s/장소번호?c=종류`) | "종류부터 정한다"는 서비스의 특징이 받은 사람에게 전해진다. 미리보기 제목에 종류를 넣을 수 있다 | 화면 쪽에 종류 이름표가 새로 필요하고, 서버의 표와 어긋나지 않게 지켜야 한다 | **선택** (운영자) |
| 메인 주소에 얹는다 (`/?p=장소번호`) | 새 경로가 없다 | 732줄짜리 메인 화면의 상태 전환을 고쳐야 한다. 미리보기를 링크마다 바꿀 수 없다. 공유로 온 방문을 가르기 어렵다 | 버림 |

운영자가 고른 것 외에, 가게 정보를 버튼 없이 바로 보여 주는 것과 `나도 뽑아 보기`를 두는
것도 운영자가 정했습니다.

## 6. 무엇을 만드는가

### 6-1. 보내는 쪽: 결과 화면의 `보내기`

```
┌──────────────────────────────────┐
│          맛있게 드세요            │
│  정하신 곳은 14일 동안 기록에     │
│  남아요                          │
│     [ 보내기 ]  [ 기록 보기 ]    │
└──────────────────────────────────┘
```

- **자리**: `여기로 정했어요`를 누른 직후 뜨는 "맛있게 드세요" 상자 안
  (`web/components/ResultScreen.tsx`). 이 상자는 기록이 실제로 남았을 때만 뜨므로, 브라우저
  저장소가 막힌 사용자에게는 `보내기`도 보이지 않습니다(만드는 쪽의 판단: 자리를 하나로
  두는 편이 단순하고, 그런 사용자는 드뭅니다).
- **보이는 조건**: 방금 정한 가게의 가게 페이지 주소가 `kakaoPlaceUrl`을 통과하고, 그 주소의
  경로에서 숫자로만 된 장소 번호를 얻을 수 있을 때만 보입니다. 카카오가 가게 페이지 주소를
  비워 보내는 가게에는 버튼이 없습니다. 눌러도 쓸모없는 링크를 만들지 않기 위해서입니다.
- **누르면**: 휴대폰의 공유 창(`navigator.share`)을 엽니다. 넘기는 것은 두 가지입니다.
  - 글: `오늘은 돈까스·우동, 연돈 어때요?` (종류 이름, 쉼표, 가게 이름, " 어때요?"). 가게 이름
    뒤에 조사를 붙이지 않는 꼴이라 받침에 따라 틀릴 일이 없습니다.
  - 주소: `{정식 주소}/s/{장소번호}?c={종류 식별자}`
- **공유 창이 없는 브라우저**(대부분의 데스크톱): 글과 주소를 한 줄씩 이어 클립보드에 복사하고
  버튼 옆에 "복사했어요"를 알립니다. 복사도 막히면 주소를 글자로 보여 주고 길게 눌러
  복사하라고 알립니다(`InstallGuide`가 하는 방식과 같습니다).
- **사용자가 공유 창을 그냥 닫은 경우**: 아무 안내도 하지 않습니다. 오류가 아닙니다.
- 가게 이름은 글에만 들어가고 주소에는 들어가지 않습니다.
- **정식 주소를 얻는 곳**: 결과 화면은 브라우저에서 도는 화면이라 서버 환경변수 `SITE_URL`을
  읽지 못합니다. 지금 열려 있는 주소의 앞부분(`window.location.origin`)을 씁니다
  (`InstallGuide`의 `copyAddress`가 쓰는 방식과 같습니다).
- **종류 식별자를 넘겨야 합니다.** 결과 화면(`ResultScreen`)은 지금 종류의 이름만 받고
  식별자는 받지 않습니다. 링크를 만들려면 식별자도 받도록 고쳐야 합니다.

### 6-2. 링크의 모양과 검사

```
https://todaybap.vercel.app/s/12345678?c=donkatsu
                              └장소번호┘  └종류 식별자┘
```

- **장소 번호**: 숫자만, 길이 상한을 둡니다(상한 값은 만드는 사람이 정합니다). 어기면 "없는
  페이지"(404)로 답합니다. 이 값은 `https://place.map.kakao.com/{장소번호}`로만 쓰이고,
  만든 주소는 다시 `kakaoPlaceUrl`을 통과해야 합니다.
- **종류 식별자**: 화면 쪽 이름표(6-4)에 있는 값일 때만 씁니다. 없거나 표에 없는 값이면
  오류로 보지 않고 **종류 없이** 가게만 보여 줍니다(6-3의 둘째 그림). 서버가 나중에 종류를
  없애거나 바꿔도 예전에 보낸 링크가 죽지 않게 하기 위해서입니다.
- 주소에 담긴 글자를 화면에 그대로 그리는 자리는 없습니다. 화면에 보이는 글자는 모두 우리
  코드 안의 것이거나 카카오 페이지가 스스로 그리는 것입니다.

### 6-3. 받는 쪽: 공유 화면 (`/s/[장소번호]`)

```
 종류를 알 때                          종류를 모를 때
┌──────────────────────────────┐    ┌──────────────────────────────┐
│           오늘은             │    │   오늘 점심, 여기 어때요?    │
│         돈까스·우동          │    │ ┌──────────────────────────┐ │
│ ┌──────────────────────────┐ │    │ │                          │ │
│ │ (카카오 가게 페이지)      │ │    │ │ (카카오 가게 페이지)      │ │
│ │  연돈  ★4.5              │ │    │ │                          │ │
│ │  메뉴 · 후기 · 사진       │ │    │ │                          │ │
│ │  (이 안에서 스크롤)       │ │    │ │                          │ │
│ └──────────────────────────┘ │    │ └──────────────────────────┘ │
│ [ 카카오에서 열기 ]          │    │ [ 카카오에서 열기 ]          │
│ [ 나도 뽑아 보기 ]           │    │ [ 나도 뽑아 보기 ]           │
└──────────────────────────────┘    └──────────────────────────────┘
```

- **화면 높이에 맞춥니다.** 머리글과 두 버튼은 항상 보이고, 가게 페이지가 남은 높이를
  차지하며 그 안에서 스크롤됩니다. 바깥 화면이 길어져 `나도 뽑아 보기`가 아래로 밀리면
  안 됩니다(3절의 실패 조건).
- **가게 페이지**: `PlaceSheet`와 같은 방식으로 끼워 넣고 같은 `SHEET_SANDBOX`를 겁니다.
- **`나도 뽑아 보기`**: 이 화면에서 강조색으로 칠한 유일한 버튼입니다. 시작 화면(`/`)으로
  가는 링크입니다. 받은 사람은 보낸 사람과 다른 곳에 있을 수 있으므로, 보낸 사람의 위치를
  물려주지 않고 자기 위치에서 새로 찾게 합니다.
- **`카카오에서 열기`**: 가게 페이지를 새 탭으로 여는 조용한 링크입니다. 끼워 넣은 화면이
  비어 보일 때의 대비책입니다. 막혔는지를 코드로 알아낼 방법이 없어 항상 둡니다.
- **서비스 이름**: 처음 온 사람이 어디에 왔는지 알 수 있게 `오늘은 뭐 먹지?`를 화면 어딘가에
  작게 둡니다. 자리와 크기는 만드는 사람이 정합니다.
- **방문 기록**: 이 화면도 방문으로 셉니다. 방문을 보내는 `VisitBeacon`은 지금 시작 화면
  (`web/app/page.tsx`)에만 붙어 있으므로 공유 화면에도 따로 붙여야 합니다. 공유로 온 방문을
  **구분해서** 세는 것은 다음 작업입니다.
- **말투와 모양**: 기존 화면의 `~해요` 말투, 글꼴, 버튼 모양(`btn` 계열)을 그대로 씁니다.

### 6-4. 화면 쪽 음식 종류 이름표

- `web/lib/`에 식별자와 이름의 짝 18개를 둡니다(파일 이름은 만드는 사람이 정합니다).
- **시험이 Go 소스와 대조합니다.** `api/internal/cuisine/cuisine.go`에서 `Cuisine{"식별자",
  "이름"}` 꼴을 모두 뽑아, 화면 쪽 표와 짝이 정확히 같은지 봅니다(한쪽에만 있는 것, 이름이
  다른 것 모두 실패). 뽑은 개수가 줄면 대조 방법이 깨진 것으로 보고 실패시킵니다
  (`errors.test.ts`의 방식과 같습니다).
- 이 표는 공유 화면과 미리보기 제목에만 씁니다. 기존 화면은 지금처럼 서버가 준 이름을 씁니다.

### 6-5. 링크 미리보기와 검색엔진

- **제목**: 종류를 알면 `오늘은 돈까스·우동`, 모르면 `오늘 점심, 여기 어때요?`. 브라우저 탭
  제목과 미리보기 제목을 같은 글자로 둡니다. **제목에 서비스 이름을 이어 붙이지 않습니다.**
  이어 붙이면 "오늘은 돈까스·우동 | 오늘은 뭐 먹지?"처럼 "오늘은"이 두 번 나오고 길어집니다.
  서비스 이름은 지금처럼 사이트 이름 항목(`og:site_name`)에만 둡니다. 이 저장소에는 페이지
  제목과 서비스 이름을 잇는 규칙이 아직 없고(`web/lib/site.ts`, `web/app/stats/page.tsx`),
  이번에도 만들지 않습니다.
- **이 화면의 주소**: 대표 주소와 미리보기 주소(`og:url`)를 이 공유 화면의 주소로 냅니다.
  사이트 공통 값은 둘 다 시작 화면("/")으로 고정되어 있어서, 덮어쓰지 않으면 공유 화면이
  시작 화면 주소를 자기 주소라고 알리게 됩니다.
- **설명**: 기존 사이트 설명을 그대로 씁니다.
- **그림**: 사이트 공통 그림 한 장을 그대로 씁니다. 가게마다 그림을 만들지 않습니다.
- **검색엔진 수집 제외**: 공유 화면에는 "수집하지 말라"는 표시를 답니다. 주소의 조합이
  끝없이 많고 내용은 카카오 페이지라 검색 결과에 올릴 것이 없습니다. `/sitemap.xml`에도
  넣지 않습니다. `robots.txt`는 고치지 않습니다(거기서 막으면 검색엔진이 "수집 제외" 표시를
  읽지 못합니다).

### 6-6. 카카오 자료와의 관계

- 링크에 담는 것은 장소 번호와 우리 종류 식별자입니다. 우리 서버와 브라우저 저장소에는
  이번 작업으로 새로 남는 것이 없습니다.
- 다만 README에는 "종류 식별자는 카카오 분류에서 계산한 값이라 저장을 피했다"는 기록이
  있습니다. 링크에 담는 것은 우리가 저장하는 것이 아니지만 같은 값을 서비스 밖으로 내보내게
  됩니다. 운영자는 이 점을 알고 이 방법을 골랐습니다(2026-11-25의 "카카오 저장 금지는 일단
  따지지 않는다"는 결정과 같은 선에 있습니다). README의 해당 절에 이 사실을 적습니다.

### 6-7. 문서

- `README.md`: 화면 그림과 설명에 공유 화면과 `보내기`를 더하고, 링크의 모양, 종류 식별자를
  링크에 담는다는 사실(6-6), "아직 없는 것들"의 요청 빈도 제한 문장에 운영자 결정을 덧붙입니다.
- `PRODUCT.md`: "화면은 다섯 개입니다"를 고칩니다.
- `docs/todo.md`: 4번 후보의 1단계를 끝난 것으로 표시합니다. 요청 빈도 제한이 먼저 와야
  한다고 적은 자리가 두 곳입니다("이 결정이 바꾸지 않는 것" 절의 마지막 문장, 4번 후보의
  "선행 조건"). 두 곳 모두에 걸지 않기로 한 결정과 날짜를 적습니다.

## 7. 다 되었는지 확인하는 방법

1. 저장소 맨 위에서 `just check`가 통과한다(Go 시험, 화면 빌드, 화면 시험, 타입 검사, 린트).
2. 화면 시험에 다음이 들어 있고 통과한다.
   - 링크 만들기와 읽기: 올바른 값, 숫자가 아닌 장소 번호, 너무 긴 장소 번호, 표에 없는 종류,
     종류가 없는 경우.
   - 보내는 글 만들기.
   - 종류 이름표와 Go 소스의 대조.
3. 로컬에서 정식 빌드를 띄우고(`cd web && npm run build && npm start`) 다음을 본다.
   - `/s/12345678?c=donkatsu`의 응답에 제목 "오늘은 돈까스·우동", 미리보기 그림 주소, 검색엔진
     수집 제외 표시가 들어 있다.
   - `/s/abc`가 404로 답한다.
   - `/s/12345678?c=없는값`이 종류 없는 화면으로 열린다.
4. 폭 320px과 390px의 화면에서 머리글과 두 버튼이 스크롤 없이 보이고, 가게 페이지가 그
   사이에서 스크롤된다.
5. 결과 화면에서 한 곳을 정하면 `보내기`가 보이고, 공유 창이 없는 브라우저에서 누르면
   글과 주소가 복사된다.
6. **운영자가 실제 휴대폰으로 확인한다**(배포 뒤, 만드는 사람이 대신할 수 없음).
   - 아이폰에서 `보내기`로 카카오톡에 보냈을 때 글과 링크가 모두 도착하는가. 글이 빠진다면
     주소를 글 안에 넣는 방식으로 바꾼다.
   - 받은 링크를 카카오톡에서 눌렀을 때 공유 화면에 가게 페이지와 두 버튼이 보이는가.
   - 대화방의 링크 미리보기에 제목과 그림이 뜨는가.

## 8. 만드는 사람에게 맡기는 것

- 새 파일의 이름과 나누는 방식. 단, 판단(링크 만들기·읽기, 글 만들기, 이름표)은 `web/lib/`에
  두고 시험을 붙입니다.
- 장소 번호의 길이 상한, 공유 화면의 여백과 글자 크기, 서비스 이름을 두는 자리.
- 경로 매개변수를 읽는 방법, 링크마다 제목을 내는 방법. 이 저장소의 Next.js는 16이라 예전
  방식과 다를 수 있으므로 `web/node_modules/next/dist/docs/`의 문서를 먼저 읽습니다.
- `보내기`를 눌렀을 때의 상태(복사됨, 복사 실패)를 어디에 두고 어떻게 알릴지.

**만드는 쪽이 정했고 운영자가 고칠 수 있는 것** (운영자가 따로 말하지 않은 부분입니다)

- `나도 뽑아 보기`는 시작 화면으로 간다(보낸 사람의 위치를 물려주지 않는다).
- `카카오에서 열기`를 항상 둔다.
- 가게 이름은 주소에 담지 않는다.
- `보내기`는 "맛있게 드세요" 상자 안에만 둔다.
- 표에 없는 종류는 오류가 아니라 종류 없는 화면으로 연다.
- 공유 화면은 검색엔진 수집에서 뺀다.
- 미리보기 그림은 사이트 공통 그림을 쓴다.
- 미리보기 제목에 서비스 이름을 이어 붙이지 않는다.

  점심 직전에 올리고 다음 주에도 다시 오는지 봅니다.
