# 홈 화면에 추가해서 앱처럼 열기 — 설계 문서

## 1. 한 문단 요약

지금은 이 서비스를 쓰려면 매번 브라우저를 열고 주소나 탭을 찾아야 합니다. 이번 변경은
서비스를 휴대폰 홈 화면에 아이콘으로 추가할 수 있게 만들고, 추가하는 방법을 화면에서
안내합니다. 홈 화면의 아이콘을 누르면 주소창이 없는 전체 화면으로 시작 화면이 곧바로
열립니다. 앱 스토어에 올리는 일은 이번 범위가 아닙니다.

## 2. 왜 필요한가

서비스를 써 본 사람에게서 받은 피드백 가운데 가장 뼈아팠던 것이 "웹 브라우저를 통해
접속해야 하니 안 쓰게 된다"였습니다. 이 서비스는 점심때마다 다시 열어야 쓸모가 있는데,
다시 여는 과정이 번거로우면 한 번 쓰고 잊힙니다.

해결하려는 것은 기능 부족이 아니라 **다시 여는 과정의 번거로움**입니다. 그래서 성공의
기준은 "홈 화면에서 한 번 눌러 시작 화면에 도달하는 것"입니다.

## 3. 목표와 목표가 아닌 것

**목표**

- 안드로이드와 아이폰에서 이 서비스를 홈 화면에 추가할 수 있고, 아이콘을 눌러 열면
  주소창 없이 시작 화면이 뜹니다.
- 한 곳을 정한 직후(`여기로 정했어요`를 누른 직후)에 홈 화면에 추가하라는 안내가
  나타납니다.
- 시작 화면에 `홈 화면에 추가` 링크가 항상 있어서, 안내를 닫은 사람도 나중에 다시 찾을 수
  있습니다.
- 이미 홈 화면에서 연 사람에게는 안내도 링크도 보이지 않습니다.

**목표가 아닌 것**

- 구글 플레이나 앱 스토어에 올리는 것. 구글 플레이는 개인 계정으로 새로 가입하면 테스터
  12명 이상이 14일 동안 참여해야 정식 출시를 신청할 수 있고, 앱 스토어는 웹사이트를 감싸기만
  한 앱이 거절되기 쉽습니다(둘 다 2026-11-19 대화에서 기억에 기대어 적은 내용이며 공식
  문서로 다시 확인하지 않았습니다). 홈 화면 추가를 먼저 만들어 반응을 본 뒤에 별도로
  판단합니다. 이번에 만든 것은 구글 플레이에 올릴 때 그대로 쓰입니다.
- 인터넷이 끊긴 상태에서의 동작. 가게 정보는 카카오에서 실시간으로만 받을 수 있어서,
  화면이 뜨더라도 할 수 있는 일이 없습니다.
- 알림 보내기.

**이렇게 되면 실패입니다**

- 서비스를 써 보기도 전에 설치부터 요구해서 처음 온 사람을 막는 것.
- 안내를 닫았는데도 계속 다시 나타나서 반복해 쓰는 사람을 방해하는 것.
- 추가할 수 없는 환경(카카오톡 안에서 열린 화면 등)에서 눌러도 아무 일도 일어나지 않는
  버튼을 보여 주는 것.
- 카카오 조회 결과가 기기에 저장되는 것(카카오가 금지합니다).

## 4. 확인된 사실과 확인되지 않은 것

**확인된 것**

- 이 저장소에 설치된 Next.js 16.3.3의 공식 안내서
  (`web/node_modules/next/dist/docs/01-app/02-guides/progressive-web-apps.md`)에 따르면,
  `web/app/manifest.ts` 파일을 두면 홈 화면 추가에 필요한 앱 정보 파일이 만들어집니다.
  같은 안내서에 "오프라인 지원 없이도 설치 창을 띄울 수 있다"고 적혀 있습니다.
- 같은 안내서의 예시는 이미 홈 화면에서 열렸는지를
  `window.matchMedia('(display-mode: standalone)')`으로 판별합니다.
- 지금 `web/` 안에는 앱 정보 파일, 뒤편에서 도는 스크립트(서비스 워커), 앱 아이콘이
  없습니다. `web/public/`에는 Next.js 기본 그림 파일만 있습니다.
- 화면은 `https://random-choice-gamma.vercel.app`에 올라가 있고(README "올려 둔 곳"),
  홈 화면 추가에 필요한 조건인 https를 이미 충족합니다.
- 지금도 `여기로 정했어요`가 실제로 기록된 직후에 "맛있게 드세요" 상자가 목록 아래에
  나타납니다(`web/components/ResultScreen.tsx`의 `closed`).

**확인되지 않은 것 — 만드는 중에 실제 기기로 확인합니다(9절)**

- 서비스 워커 없이도 안드로이드 Chrome이 설치 버튼에 필요한 신호
  (`beforeinstallprompt`)를 실제로 보내 주는지.
- 아이폰에서 Safari로 남긴 기록이 홈 화면에 추가한 앱에서 보이는지. 아이폰은 둘의 저장
  공간을 따로 쓰는 것으로 알고 있으나 실제 기기로 확인하지 않았습니다.
- 홈 화면에서 연 상태에서 위치 권한, 가게 창, 새 탭으로 열리는 링크, 뒤로 가기가 브라우저에서와
  같게 동작하는지.

## 5. 검토한 방식과 고른 방식

세 방식 모두 안내 화면은 같고, 뒤편에서 도는 스크립트(서비스 워커)를 얼마나 쓰는지가
다릅니다.

| 방식 | 내용 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| 앱 정보 파일·아이콘·안내만 추가 **(고른 방식)** | Next.js에 내장된 파일 규칙만 쓰고 새 라이브러리를 설치하지 않습니다. | 바뀌는 곳이 가장 적고, 기기에 남은 옛 파일 때문에 고친 화면이 전달되지 않는 종류의 문제가 생기지 않습니다. | 인터넷이 끊긴 채로 열면 브라우저의 기본 오류 화면이 뜹니다. |
| 위에 최소한의 서비스 워커 추가 | 인터넷이 끊겼을 때 "인터넷 연결이 필요해요" 화면 하나만 보여 줍니다. | 끊긴 상태에서도 서비스 모양의 안내가 보입니다. | 서비스 워커는 한 번 내보내면 사용자 기기에 남아서, 갱신을 잘못 다루면 고친 화면이 전달되지 않습니다. |
| 라이브러리로 화면 파일 전체를 기기에 저장 | 두 번째 실행부터 화면이 더 빨리 뜹니다. | 속도. | 새 의존성이 생기고, 설정을 잘못해 `/api` 응답까지 저장하면 카카오의 저장 금지를 어깁니다. |

**고른 이유(사용자가 2026-11-19에 결정)**: 풀려는 문제는 다시 여는 번거로움이고 이것은
아이콘과 안내만으로 풀립니다. 이 서비스는 어차피 인터넷이 있어야 동작하므로 나머지 두
방식의 이점이 작습니다. 나중에 필요해지면 첫 방식 위에 두 번째 방식을 덧붙일 수 있습니다.

**되돌아갈 조건**: 실제 안드로이드 기기에서 서비스 워커가 없어 설치 신호가 오지 않으면,
두 번째 방식(아무것도 저장하지 않는 최소한의 서비스 워커)으로 바꿉니다. 그때도 `/api`
응답은 저장하지 않습니다.

## 6. 사용자가 보게 되는 것

### 6-1. 안내가 나타나는 두 자리 (사용자가 결정)

```
시작 ──▶ 위치 검색 ──▶ 후보 고르기 ──▶ 결과 ──▶ [여기로 정했어요]
 ▲                                                    │
 │                                                    ▼
 └ 아래쪽에 `홈 화면에 추가` 링크가 항상 있음        "맛있게 드세요" 상자 아래에
                                                      안내 상자가 따로 나타남
```

처음 들어오자마자 안내하는 방식은 고르지 않았습니다. 써 보기도 전에 설치를 요구하면
무시되기 쉽고, "처음 온 사람이 설명 없이 쓸 수 있어야 한다"는 제품 원칙과 부딪히기
때문입니다.

### 6-2. 결과 화면의 안내 상자 (사용자가 세 가지 모양 중에서 고름)

`여기로 정했어요`가 실제로 기록된 직후, 기존 "맛있게 드세요" 상자 **아래에 별도의 상자**로
나타납니다. 기존 상자 안에 한 줄을 끼워 넣는 모양은 눈에 띄지 않아서, 화면 아래에서 올라와
목록을 가리는 창은 방금 정한 가게를 확인하는 순간을 가려서 고르지 않았습니다.

```
┌──────────────────────────────┐
│        맛있게 드세요          │  ← 지금 있는 상자(그대로)
│ 정하신 곳은 14일 동안 기록에 남아요 │
│        [기록 보기]            │
└──────────────────────────────┘
┌──────────────────────────────┐
│                           ✕  │  ← 새 상자. 종이색 바닥
│      내일도 오실 건가요?       │
│ 홈 화면에 추가해 두면 브라우저를  │
│ 열지 않고 바로 시작할 수 있어요  │
│     [홈 화면에 추가하기]       │  ← 강조색 버튼
└──────────────────────────────┘
```

- `✕`를 누르면 상자가 사라지고, 그 뒤로는 다른 가게를 정해도 결과 화면에 다시 나타나지
  않습니다.
- 기록이 실제로 남지 않은 경우(저장소가 막힌 브라우저)에는 "맛있게 드세요" 상자와 마찬가지로
  나타나지 않습니다.

### 6-3. 시작 화면의 링크

`최근 기록 보기` 옆에 같은 모양의 작은 링크 `홈 화면에 추가`를 둡니다. 이 링크는 결과
화면의 상자를 닫은 뒤에도 남습니다.

링크는 결과 화면 상자의 `홈 화면에 추가하기` 버튼을 누른 것과 같은 일을 합니다. 즉 권유
문구("내일도 오실 건가요?")를 거치지 않고 6-4의 내용으로 곧바로 갑니다.

- 설치 신호가 온 브라우저: 상자를 그리지 않고 브라우저의 설치 확인 창을 곧바로 띄웁니다.
- 아이폰·아이패드, 다른 앱 안에서 열린 화면: 다른 화면으로 가지 않고, 시작 화면의 소개 글
  자리에 아래 상자가 펼쳐집니다. 펼쳐진 동안에는 링크를 감춥니다. `✕`를 누르면 소개 글과
  링크가 돌아옵니다.

```
┌──────────────────────────────┐        ┌──────────────────────────────┐
│                           ✕  │        │                           ✕  │
│      홈 화면에 추가하기        │        │      홈 화면에 추가하기        │
│ 브라우저를 열지 않고 바로      │        │ 여기서는 추가할 수 없어요.     │
│ 시작할 수 있어요              │        │ 먼저 Safari나 Chrome에서      │
│ 1. 화면 아래의 공유 버튼을 눌러요│        │ 이 페이지를 열어 주세요.       │
│ 2. 목록을 내려 홈 화면에 추가를 │        │      [주소 복사하기]          │
│    눌러요                     │        └──────────────────────────────┘
│ 3. 오른쪽 위의 추가를 눌러요    │         (다른 앱 안에서 열린 화면)
└──────────────────────────────┘
 (아이폰·아이패드)
```

시작 화면에는 이미 강조색 버튼(`지금 있는 곳에서 찾기` 또는 `OOO 다시 찾기`)이 있으므로,
이 상자 안의 `주소 복사하기`는 강조색으로 칠하지 않고 조용한 버튼(`btn-quiet`)으로 그립니다.
결과 화면에는 칠해진 강조색 버튼이 없어서 6-2의 버튼은 강조색을 씁니다.

### 6-3-1. 닫았다는 표시를 남기는 때

| 동작 | 표시를 남기는가 | 까닭 |
|---|---|---|
| 결과 화면 상자의 `✕` | 남깁니다 | 권유를 거절한 것입니다. |
| 결과 화면에서 버튼을 눌러 뜬 브라우저 설치 확인 창을 취소 | 남깁니다 | 역시 거절입니다. 남기지 않으면 다음 방문에 상자가 다시 나타납니다. |
| 시작 화면에서 펼친 상자의 `✕` | 남기지 않습니다 | 스스로 눌러 구경한 것이지 권유를 거절한 것이 아닙니다. |
| 시작 화면 링크로 뜬 설치 확인 창을 취소 | 남기지 않습니다 | 위와 같습니다. |

브라우저의 설치 신호는 한 번 쓰면 그 방문 동안 다시 쓸 수 없습니다. 그래서 설치 확인 창을
취소하면 그 방문 동안은 6-4의 "그 밖" 상황이 되어 시작 화면의 링크도 사라지고, 다음 방문에
신호가 다시 오면 링크가 돌아옵니다.

### 6-4. 버튼을 누른 뒤 — 기기에 따라 넷으로 나뉨

두 자리의 안내 상자는 같은 부품이고, 기기에 따라 내용이 달라집니다.

| 상황 | 결과 화면의 상자 | 시작 화면의 링크 | 버튼·링크를 눌렀을 때 |
|---|---|---|---|
| 브라우저가 설치 신호를 보내 준 경우(안드로이드 Chrome 등) | 보임 | 보임 | 브라우저의 설치 확인 창이 곧바로 뜹니다. 설치를 마치면 상자와 링크가 사라집니다. |
| 아이폰·아이패드의 브라우저 | 보임 | 보임 | 상자 안에 순서가 펼쳐집니다: ① 공유 버튼을 눌러요 ② 목록을 내려 `홈 화면에 추가`를 눌러요 ③ 오른쪽 위의 `추가`를 눌러요 |
| 다른 앱 안에서 열린 화면(카카오톡, 네이버, 인스타그램 등) | 보임 | 보임 | "여기서는 추가할 수 없어요. Safari나 Chrome에서 이 페이지를 열어 주세요"와 `주소 복사하기` 버튼이 나옵니다. |
| 이미 홈 화면에서 연 경우 | 안 보임 | 안 보임 | — |
| 그 밖(설치 신호가 오지 않은 브라우저) | 안 보임 | 안 보임 | — |

마지막 줄의 까닭: 눌러도 아무 일도 일어나지 않는 버튼을 보여 주지 않기 위해서입니다.

### 6-5. 홈 화면에 놓이는 모습

아이콘과 이름은 홈 화면에 추가하는 순간 그 기기에 굳습니다. 나중에 바꿔도 이미 추가한
사람의 기기에는 잘 반영되지 않고, 아이폰은 지우고 다시 추가해야 바뀝니다. 그래서 둘 다
사용자가 미리 정했습니다(2026-11-19).

- 이름: 앱 이름과 아이콘 아래 이름 모두 `오늘은 뭐 먹지?`로 같게 둡니다. 아이콘 아래 칸이
  좁아 일부 기기에서 끝이 "…"으로 잘릴 수 있다는 것을 알고 고른 것입니다. `뭐 먹지?`로
  줄이는 안은 고르지 않았습니다.
- 아이콘: **웃는 얼굴이 그려진 귀여운 밥그릇**입니다. 종이색 바탕(`--background`, `#faf9f7`)
  위에 강조색(`--accent`, `#b8552f`) 그릇이 있고, 그릇 위로 흰 밥이 둥글게 올라와 있으며,
  그릇 몸통에 점 두 개의 눈과 웃는 입, 볼의 분홍색 점이 있습니다. 테두리 선은 본문 글자색
  (`--foreground`)입니다. 글자는 넣지 않습니다. 노렌이나 글자를 쓴 안, 남색 그릇 안, 선 없는
  남색 바탕 안은 고르지 않았습니다. 아래는 사용자가 고른 스케치이며, 선 굵기와 비율은 만들
  때 다듬습니다.

  ```svg
  <svg viewBox="0 0 104 104">
    <rect width="104" height="104" fill="#faf9f7"/>
    <path d="M24 54a28 26 0 0 1 56 0z" fill="#ffffff" stroke="#1c1a17" stroke-width="3" stroke-linejoin="round"/>
    <path d="M18 54h68q0 28-24 32v4H42v-4Q18 82 18 54z" fill="#b8552f" stroke="#1c1a17" stroke-width="3" stroke-linejoin="round"/>
    <circle cx="42" cy="68" r="3" fill="#1c1a17"/><circle cx="62" cy="68" r="3" fill="#1c1a17"/>

  </svg>
  ```

  가장자리가 잘려도 되는 크기의 아이콘(안드로이드가 원이나 둥근 네모로 잘라 씁니다)에서는
  그릇과 얼굴이 잘리지 않도록 그림을 가운데로 더 모읍니다.
- 열었을 때: 주소창 없는 전체 화면, 시작 화면부터. 켜지는 동안의 바탕색은 나무색
  (`#e8d6b4`)입니다.

## 7. 저장하는 것

안내 상자를 닫았다는 표시 하나를 브라우저 `localStorage`에 새 열쇠로 남깁니다. 기록
(`random-choice.visits.v1`)이나 회피 설정(`random-choice.avoid.v1`)과 **다른 열쇠**를 씁니다.
이 값은 사용자가 만든 설정이고 카카오 조회 결과가 아니므로 저장 금지와 무관합니다.
그 밖에 새로 저장하는 것은 없고, 서비스 워커를 두지 않으므로 화면 파일이나 `/api` 응답이
기기에 따로 쌓이지도 않습니다.

저장소가 막힌 브라우저에서는 닫았다는 표시를 남길 수 없습니다. 이때는 결과 화면의 상자가
애초에 나타나지 않으므로(6-2) 문제가 되지 않습니다.

## 8. 바뀌는 곳

| 무엇을 | 어디에 | 비고 |
|---|---|---|
| 앱 정보 파일 | `web/app/manifest.ts` (새 파일) | 이름, 짧은 이름, 시작 주소 `/`, 전체 화면 표시, 바탕색, 아이콘 목록 |
| 아이콘 | `web/app/` 또는 `web/public/` (새 파일) | 192·512 크기, 가장자리가 잘려도 되는 512 크기, 아이폰용 180 크기 |
| 기기 판별과 닫음 표시 | `web/lib/install.ts` (새 파일) + 시험 | 기존 `web/lib/`의 방식대로 브라우저 값을 인자로 받는 함수로 만들어 node에서 시험합니다 |
| 안내 상자 부품 | `web/components/InstallGuide.tsx` (새 파일) | 결과 화면과 시작 화면이 함께 씁니다 |
| 결과 화면 | `web/components/ResultScreen.tsx` | "맛있게 드세요" 상자 아래에 부품을 놓습니다 |
| 시작 화면 | `web/components/StartScreen.tsx` | 링크와, 소개 글 자리에 펼쳐지는 부품 |
| 설치 신호 받기 | `web/app/page.tsx` | 설치 신호는 페이지가 열린 뒤 한 번만 오므로, 어느 화면에 있든 놓치지 않도록 여기서 받아 둡니다 |
| 문서 | `README.md`, `PRODUCT.md`, `DESIGN.md` | 화면 설명, 기기에 남는 것 목록, 알려진 한계, 안내 상자의 모양 규칙 |

지키는 기존 규칙: 글자는 나뭇결 위에 직접 놓지 않고 종이색 바닥 위에 둡니다. 강조색은 한
화면에서 주요 버튼에만 씁니다. 움직임은 `rise` 하나뿐입니다. 말투는 `~해요` 체입니다.
누를 수 없는 상태의 버튼은 `disabled` 대신 `aria-disabled`를 씁니다.

## 9. 다 되었는지 확인하는 방법

**컴퓨터에서**

- `web/`에서 시험·린트·빌드가 모두 통과합니다(`npm test`, `npm run lint`, `npm run build`).
- 기기 판별 함수의 시험이 6-4의 다섯 상황을 모두 다룹니다.
- 올린 주소에서 `/manifest.webmanifest`가 열리고, Chrome 개발자 도구의 Application 탭이
  "설치 가능"으로 표시합니다.
- 390px 폭 화면에서 6-2·6-3의 상자가 목업과 같은 자리에 나타나고, `✕` 뒤에 결과 화면에서
  다시 나타나지 않습니다.

**실제 기기에서 (사람이 직접)**

1. 안드로이드 Chrome: 버튼을 누르면 설치 확인 창이 뜨고, 설치 뒤 홈 화면 아이콘으로 열면
   주소창 없이 시작 화면이 뜹니다. 설치 신호가 오지 않으면 5절의 "되돌아갈 조건"을 따릅니다.
2. 아이폰 Safari: 순서 안내대로 따라 하면 홈 화면에 추가됩니다. 안내의 버튼 위치·이름이
   실제 화면과 맞는지 봅니다.
3. 카카오톡으로 받은 링크를 눌러 열었을 때: "여기서는 추가할 수 없어요" 안내가 나오고
   `주소 복사하기`가 동작합니다.
4. 홈 화면에서 연 상태로 한 바퀴: 위치 권한 → 후보 → 결과 → 가게 창 열고 닫기 →
   `여기로 정했어요` → 기록. 모든 화면에서 화면 안의 버튼만으로 시작 화면에 돌아올 수
   있어야 합니다(아이폰은 이 상태에서 브라우저의 뒤로 가기 버튼이 없습니다).
5. 두 기기의 홈 화면에서 아이콘 아래 이름이 어떻게 보이는지(잘리는지) 확인해 README에
   적습니다. 잘리더라도 이름은 바꾸지 않습니다(6-5).
6. 아이폰에서 Safari로 한 곳을 정한 뒤 홈 화면에 추가하고, 그 기록이 앱에서 보이는지
   확인합니다. 보이지 않으면 README의 "지금 아는 한계"에 적습니다.

## 10. 주의할 것

- **주소를 바꾸면 설치한 사람이 끊깁니다.** 홈 화면 아이콘과 기기에 남은 기록은 지금
  주소(`random-choice-gamma.vercel.app`)에 묶여 있습니다. 나중에 주소를 바꾸면 이미 추가한
  사람은 다시 추가해야 하고 기록도 넘어가지 않습니다. 주소를 바꿀 계획이 있다면 사람들에게
  알리기 전에 바꾸는 편이 낫습니다.
- **아이폰에서는 이미 추가했는지 브라우저 안에서 알 수 없습니다.** 그래서 홈 화면에 추가한
  사람이 Safari로 다시 들어오면 안내가 또 보일 수 있습니다. `✕`로 닫으면 그만입니다.
- **push해도 자동으로 올라가지 않습니다.** 실제 기기 확인은 README "다시 올릴 때"의 절차로
  올린 뒤에 할 수 있습니다.

## 11. 만드는 사람에게 맡기는 것

- 아이콘 파일을 만드는 방법(직접 그린 그림 파일을 둘지, Next.js의 아이콘 생성 규칙을 쓸지).
- 다른 앱 안에서 열린 화면인지 판별할 때 볼 앱의 목록. 카카오톡은 반드시 포함합니다.
- `주소 복사하기`가 막힌 환경에서의 대비(예: 주소를 글자로 보여 주어 길게 눌러 복사).
- 안내 상자가 펼쳐질 때 화면 낭독기와 키보드 초점의 처리. 결과 화면이 이미 쓰는 방식
  (`web/components/ResultScreen.tsx`의 초점 이동)을 따릅니다.
- 닫음 표시를 담는 열쇠의 이름.

## 12. 이 문서를 쓰며 글쓴이가 정한 것 (사용자 확인 대상)

사용자가 말한 것이 아니라 글쓴이가 채운 부분입니다.

1. 켜지는 동안의 바탕색을 나무색(`#e8d6b4`)으로 둔 것(6-5). 아이콘 바탕은 종이색이지만
   열린 뒤의 화면 바탕이 나무색이라 그쪽에 맞췄습니다.
2. 아이콘에 글자를 넣지 않는 것(6-5).
3. 설치 신호가 오지 않은 브라우저에서는 상자와 링크를 아예 감추는 것(6-4 마지막 줄).
   컴퓨터의 Chrome처럼 신호가 오는 곳에서는 휴대폰이 아니어도 보입니다.
4. 시작 화면의 "이 기기에는 마지막 검색어와 정한 가게(14일)만 남아요" 문장은 고치지 않고,
   닫음 표시는 README의 저장 범위 설명에만 더하는 것. 지금도 회피 설정이 그 문장에 없이
   저장되고 있어 같은 기준을 따랐습니다.
5. 안내 상자의 문구는 6-2와 6-3의 그림에 적힌 그대로 쓰는 것(사용자가 목업으로 본 문구입니다).
6. 닫았다는 표시를 남기는 때를 6-3-1의 표처럼 나눈 것.
7. 시작 화면 상자의 `주소 복사하기`를 강조색 없이 그리는 것(6-3). 목업에서는 강조색이었으나
   "한 화면에 강조색 버튼은 하나"라는 기존 디자인 규칙을 우선했습니다.
