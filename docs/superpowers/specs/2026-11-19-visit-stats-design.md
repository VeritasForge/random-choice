# 접속 통계 보기 — 설계 문서

## 1. 한 문단 요약

지금은 이 서비스를 하루에 몇 명이 쓰는지 알 방법이 없습니다. 이번 변경은 방문이 일어날
때마다 "누가(익명 ID) 언제 왔는지" 한 줄을 무료 데이터베이스에 쌓고, 운영자 한 사람만
비밀번호로 들어가는 `/stats` 화면에서 일·주·월 단위의 방문자 수를 막대 그래프와 표로
보여 줍니다. 추가 비용은 내지 않습니다.

## 2. 왜 필요한가

운영자가 원하는 것은 서비스를 고칠 근거입니다. 처음 요청은 "하루 방문자 수는 물론,
접속한 사람들이 어떤 경로로 움직이고 어디서 멈추는지 알고 싶다. 이를 통해 시스템을
개선하고 싶다"였습니다. 화면별 경로와 이탈 지점까지 한 번에 만드는 안을 보고는 "너무
복잡하다, 우선은 간단하게 일·주·월별 접속 통계만 보자"로 범위를 줄였습니다.

따라서 이번에 만드는 것은 접속 통계 하나이고, 경로 분석은 나중 일입니다.

## 3. 목표와 목표가 아닌 것

**목표**

- 운영자가 `/stats`에서 일별·주별·월별 방문자 수(사람)와 방문 횟수를 봅니다.
- 같은 브라우저로 여러 날 들어온 사람을 같은 사람으로 셉니다.
- 몇 달 전 기록도 남아 있어 월끼리 비교할 수 있습니다.
- Vercel Hobby 플랜과 무료 데이터베이스 한도 안에서 돌아갑니다.
- `/stats`는 운영자만 봅니다.

**목표가 아닌 것**

- 화면별 이동 경로, 이탈 지점, 버튼 누름 횟수. 이번에는 수집하지도 않습니다(운영자가
  "접속만 수집"을 골랐습니다). 나중에 추가하면 그때부터의 기록만 생깁니다.
- 재방문율 같은 파생 지표, 기간 직접 지정, 내려받기.
- 수집 요청의 빈도 제한. 아래 9절의 한계로 남깁니다.
- 여러 운영자 계정.

**이렇게 되면 실패입니다**

- 통계 수집 때문에 서비스 화면이 느려지거나 오류 안내가 뜨는 것.
- 카카오 조회 결과(가게 목록·좌표·거리·분류)가 데이터베이스에 들어가는 것.
- 비밀번호를 모르는 사람이 통계를 보는 것.
- 요금이 청구되는 것.

## 4. 확인된 사실과 확인되지 않은 것

**공식 문서에서 확인한 것 (2026-11-19)**

- Vercel Web Analytics는 Hobby 플랜에서 무료이지만 볼 수 있는 기간이 최근 1개월만
  보장되고, 방문자를 구분하는 값이 하루마다 바뀌어 여러 날에 걸친 같은 사람을 알 수
  없습니다. 월별 비교와 "같은 사람" 기준을 채우지 못해 쓰지 않습니다.
- Vercel의 비밀번호 보호 기능은 Hobby 플랜에서 쓸 수 없습니다. 그래서 비밀번호 확인을
  직접 만듭니다.
- Neon Postgres 무료 플랜: 영구 무료, 카드 등록 불필요, 프로젝트당 저장 1GB, 월 100
  CU-hours(가장 작은 사양으로 400시간). 5분간 요청이 없으면 잠들고(끌 수 없음) 다음
  요청에서 수백 ms 안에 깨어납니다. 한도를 넘으면 요금이 아니라 다음 달까지 정지이며
  데이터는 지워지지 않습니다. 연결 풀링이 포함됩니다.

**저장소에서 확인한 것**

- 화면 다섯 개가 모두 주소 `/` 하나에서 바뀝니다(`web/app/page.tsx`).
- 브라우저는 화면 서버의 `/api/v1/...`로만 요청하고, 화면 서버가 비밀값 헤더
  `X-Internal-Key`를 붙여 Go 서버로 넘깁니다(`web/lib/proxy.ts`,
  `api/internal/httpapi/handler.go`). 지금 중계는 GET만 다룹니다.
- Go 서버는 외부 라이브러리를 하나도 쓰지 않습니다(`api/go.mod`에 require가 없음).
- 환경변수는 실서비스에만 넣고 미리보기 배포에는 넣지 않습니다(README "환경변수").
- 브라우저 저장 키는 `random-choice.<이름>.v1` 형식입니다(`web/lib/visits.ts`,
  `web/lib/anchor.ts`).
- 시작 화면에 "이 기기에는 마지막 검색어와 정한 가게(14일)만 남아요"라는 문장이
  있습니다(`web/components/StartScreen.tsx`).

**확인되지 않은 것**

- Vercel을 거쳐 Neon을 붙일 때 0원짜리 플랜을 고를 수 있는지, 결제 수단을 요구하는지.
  Vercel 문서는 "모든 플랜에서 쓸 수 있다"고만 하고 소개 페이지는 "0달러부터"라고만
  적습니다. 설치 단계에서 드러나므로 거기서 확인합니다(아래 "누가 무엇을 하는가").
- Vercel 위에서 Go 서버가 요청 사이에 데이터베이스 연결을 유지하는지. 만드는 사람이
  확인하고, 유지되지 않는다면 Neon의 풀링용 연결 주소를 쓰는 것으로 대응합니다.
- 익명 ID 보관을 법적으로 알려야 하는지. 조사하지 않았습니다.

## 5. 검토한 방법들

| 방법 | 내용 | 버린 이유 또는 고른 이유 |
|---|---|---|
| Vercel Web Analytics | 패키지 한 줄 추가 | 보장 기간 1개월, 여러 날에 걸친 같은 사람 구분 불가, Hobby에서는 버튼 누름 수집 불가 |
| PostHog Cloud 무료 | 외부 분석 서비스에 이벤트 전송 | 경로 분석까지 바로 되지만 운영자가 데이터를 직접 갖는 쪽을 골랐습니다 |
| Umami Cloud 무료 | 가벼운 외부 통계 서비스 | 위와 같음 |
| **직접 만들기 (선택)** | Go 서버에 수집 경로를 더하고 무료 Postgres에 쌓은 뒤 자체 화면에서 조회 | 운영자가 선택. 데이터가 자기 계정에 남고, 나중에 경로 분석으로 넓힐 수 있습니다 |

직접 만들기 안에서도 "경로 이벤트까지 미리 수집해 두기"를 권했으나, 운영자는 "접속만
수집"을 골랐습니다.

## 6. 전체 흐름

```
[수집]
방문자 브라우저 ──① POST /api/v1/visits──▶ 화면 서버(web/) ──② 비밀값 헤더를 붙여 전달──▶ Go 서버(api/) ──③ 한 줄 저장──▶ Neon Postgres

[조회]
운영자 브라우저 ──④ /stats + 비밀번호──▶ 화면 서버 ──⑤ 비밀값 헤더를 붙여 GET /api/v1/stats──▶ Go 서버 ──⑥ 집계 조회──▶ Neon Postgres
```

- ①~②와 ⑤는 기존 조회와 같은 중계 방식을 그대로 씁니다. Go 서버의 새 경로 둘은 모두
  `X-Internal-Key`를 요구합니다.
- ④의 비밀번호 확인은 화면 서버에서만 일어납니다. Go 서버는 비밀번호를 모릅니다.

## 7. 운영자가 정한 것

1. **직접 만든다. 비용은 내지 않는다.**
2. **같은 사람의 기준은 브라우저에 계속 남는 익명 ID다.** `localStorage`에 무작위 ID를
   한 번 만들어 두고 지울 때까지 씁니다.
3. **익명 ID를 화면에서 따로 안내하지 않는다.** 대신 시작 화면 문장에서 "만"을 빼
   사실과 어긋나지 않게 합니다. 예: "이 기기에는 마지막 검색어와 정한 가게가 14일 동안
   남아요."
4. **수집하는 것은 접속뿐이다.**
5. **웹 화면에서 본다. 운영자 혼자만 들어간다.** 비밀번호 하나를 환경변수에 두고
   브라우저의 기본 로그인 창(HTTP Basic 인증)으로 묻습니다. 숨긴 주소에 기대지 않습니다.
6. **일·주·월 단추로 단위를 바꾸고, 방문자 수를 막대 그래프로, 그 아래에 표를 둔다.**

```
/stats                              [ 일 ] [ 주 ] [ 월 ]

 40 ┤
 20 ┤      ▇▇    ▇▇    ▇▇
    ┤ ▇▇   ██    ██    ██    ▂▂    ▂▂
  0 ┴─13───14────15────16────17────18────19
      ■ 방문자

 날짜          방문자   방문 횟수
 11/19 (목)       5        8
 11/18 (수)       7       10
 …
```

## 8. 설계하면서 제안한 것

아래는 운영자가 직접 고른 것이 아니라 대화에서 제안한 내용입니다. 운영자는 반대하지
않았지만 하나씩 확인하지도 않았으므로, 이 문서를 읽으며 확인합니다.

**기록**

- 방문 1건을 보내는 때는 둘입니다. 화면을 처음 열었을 때, 그리고 가려져 있던 탭이
  다시 보이게 됐을 때입니다. 두 경우 모두 **그 탭에서 마지막으로 보낸 지 30분이 지나지
  않았으면 보내지 않습니다**(`sessionStorage`에 마지막으로 보낸 시각을 둡니다). 그래서
  새로 고침이나 잠깐 다른 앱을 다녀온 것은 방문으로 세지 않습니다.
- 탭을 닫았는지가 아니라 30분을 기준으로 삼는 이유: 휴대폰 브라우저는 탭을 며칠씩
  살려 둡니다. 탭을 열 때만 보내면, 월요일에 연 탭으로 화·수·목 점심마다 돌아오는
  사람이 월요일 하루만 잡혀 일별 방문자가 실제보다 적게 나옵니다. 수집하지 않은 방문은
  나중에 채울 수 없습니다.
- 한 줄에 담는 것은 익명 ID와 시각뿐입니다. 시각은 서버가 받은 때로 찍습니다. IP 주소,
  브라우저 정보, 위치, 검색어, 카카오에서 받은 어떤 값도 담지 않습니다.
- 전송이 실패하면 아무 안내 없이 넘어갑니다. 화면을 그리는 일을 기다리게 하지 않습니다.
- 지우지 않고 계속 보관합니다. 한 줄이 수십 바이트라 1GB 한도까지는 수천만 건입니다.

**집계**

- 날짜는 한국 시간 기준이고, 한 주는 월요일에 시작합니다.
- 숫자는 둘입니다. 방문자는 그 기간에 나타난 서로 다른 익명 ID의 수, 방문 횟수는 그
  기간의 줄 수입니다. 주·월의 방문자는 그 기간 전체에서 중복을 뺀 수이므로 일별
  방문자의 합과 다릅니다.
- 막대는 방문자만 그립니다. 방문 횟수는 표에서 봅니다.

**운영자 본인 방문 빼기**

- `/stats`에 비밀번호로 들어간 브라우저는 그 뒤로 방문을 보내지 않습니다
  (`localStorage`에 표시를 둡니다). 방문자가 적은 초기에 운영자의 방문이 숫자를 크게
  흔들기 때문입니다.
- 한계: 브라우저마다 따로이고, 표시를 두기 전에 이미 쌓인 방문은 그대로 남습니다.

**그래프**

- 외부 그래프 라이브러리를 더하지 않고 SVG로 직접 그립니다.

## 9. 알려진 한계

- **가짜 방문을 막지 못합니다.** `/api/v1/visits`는 화면 주소를 거치면 누구나 부를 수
  있어, 스크립트로 숫자를 부풀릴 수 있습니다. 이번에는 입력값 검사(익명 ID 형식, 본문
  크기)만 넣습니다. 빈도 제한은 서비스 전체의 미정 과제로 이미 남아 있습니다.
- **브라우저 저장소를 지우거나 다른 기기를 쓰면 다른 사람으로 셉니다.**
- **저장소를 쓸 수 없는 브라우저(일부 사생활 보호 모드)의 방문은 세지 않습니다.**
- **자바스크립트를 실행하지 않는 방문(대부분의 봇)은 세지 않습니다.** 실행하는 봇은
  섞입니다.
- **데이터베이스가 잠든 뒤 첫 요청은 수백 ms 늦습니다.** 수집은 화면과 무관하게
  보내므로 방문자는 느끼지 못하고, `/stats`를 여는 운영자만 가끔 겪습니다.
- **미리보기 배포에서는 수집도 조회도 되지 않습니다.** 환경변수를 실서비스에만 넣는
  기존 방침을 따릅니다.

## 10. 함께 바뀌는 문서와 문구

데이터베이스가 생기면 지금 문서의 몇 문장이 사실과 달라집니다. 같은 작업에서 고칩니다.

| 어디 | 지금 | 바꿀 방향 |
|---|---|---|
| `web/components/StartScreen.tsx` 안내 문장과 그 위 주석 | "…정한 가게(14일)만 남아요" | "만"을 빼고, 주석의 "서버에는 저장소가 없고"도 사실대로 |
| `PRODUCT.md` 운영 맥락 | "서버에는 저장소가 없습니다" | 카카오 조회 결과는 저장하지 않고, 접속 통계용 익명 ID와 시각만 저장한다고 적기 |
| `PRODUCT.md` 원칙 3 | "저장하는 것은 사용자가 직접 정한 것뿐이며, 무엇이 어디에 남는지를 숨기지 않습니다" | 접속 통계용 익명 기록을 예외로 밝히기. 화면에서 따로 안내하지 않기로 한 결정도 함께 적기 |
| `README.md` "서버에 저장소가 없는 이유" | 서버는 아무것도 남기지 않는다 | 카카오 결과를 남기지 않는다는 뜻으로 좁히고, 접속 통계 저장을 따로 설명 |
| `README.md` 환경변수 표 | 네 자리 | 아래 두 값을 더하기 |

새 환경변수(이름은 만드는 사람이 정해도 됩니다):

- `api` 프로젝트: 데이터베이스 연결 주소. 없으면 서버는 그대로 뜨고 두 새 경로만
  "설정되지 않음"으로 답합니다(카카오 열쇠가 없을 때와 같은 방식).
- `random-choice` 프로젝트: `/stats` 비밀번호. 없으면 `/stats`는 아무도 들어가지 못합니다
  (비어 있다고 열어 두지 않습니다).

## 11. 만드는 사람에게 맡기는 것

- 테이블과 인덱스의 정확한 모양, 테이블을 만드는 방법(SQL 파일을 저장소에 두고 한 번
  실행하는 정도면 충분합니다).
- Go에서 Postgres에 붙는 방법. 외부 라이브러리가 처음 들어오게 되므로 무엇을 왜
  골랐는지 남겨 주세요. 시험은 이 저장소의 방식대로 가짜 저장소를 끼워 넣을 수 있게
  합니다.
- 익명 ID의 형식과 저장 키 이름(기존 `random-choice.<이름>.v1` 형식을 따릅니다).
- 방문을 보내는 방법(`fetch`의 `keepalive`, `sendBeacon` 등)과 보내는 시점.
- Next.js에서 `/stats`의 비밀번호를 확인하는 자리. 이 저장소가 쓰는 Next.js 16의 문서를
  먼저 확인해 주세요. 비밀번호 비교는 Go 서버의 비밀값 비교처럼 길이와 내용이 응답
  시간에 드러나지 않게 합니다.
- 기본으로 보여 줄 기간. 제안: 일 단위는 최근 30일, 주 단위는 최근 12주, 월 단위는 최근
  12개월. 방문이 없는 날도 0으로 보여 줍니다.
- `/stats` 화면의 세부 모양. `DESIGN.md`의 색과 글자 규칙을 따르되, 방문자용 화면이
  아니므로 장식은 필요 없습니다. 검색 엔진에 잡히지 않게 표시합니다.
- 로컬 개발에서 데이터베이스 없이 화면을 확인하는 방법.

## 12. 누가 무엇을 하는가

운영자는 Neon에 따로 가입하지 않고 **Vercel을 거쳐** 데이터베이스를 붙이기로 했고,
그 설치부터 배포까지를 만드는 쪽(AI 작업자)에게 맡겼습니다("Vercel 도구로 알아서
해 달라"). 따라서 아래를 모두 만드는 쪽이 Vercel 명령줄 도구로 합니다.

- Vercel에서 Neon을 추가하고 `api` 프로젝트에 연결합니다. 연결 주소는 Vercel이
  환경변수로 자동 등록합니다.
- 테이블을 만듭니다.
- `/stats` 비밀번호를 무작위로 만들어 `random-choice` 프로젝트에 등록하고, 운영자에게
  한 번 알려 줍니다. 저장소에는 남기지 않습니다.
- `just deploy`로 실서비스에 올리고 13절을 확인합니다.

지킬 것:

- **0원짜리 플랜이 보이지 않거나 결제 수단을 요구하면 설치를 멈추고 운영자에게
  묻습니다.** 비용을 내지 않는 것이 이 작업의 조건입니다.
- 환경변수는 실서비스(Production)에만 둡니다. 미리보기 배포마다 데이터베이스 복사본을
  만드는 기능은 켜지 않습니다.
- 약관 동의나 브라우저 로그인처럼 운영자 본인만 할 수 있는 단계가 나오면 그 단계만
  운영자에게 넘깁니다.
- 알아 둘 점: 이 연동을 나중에 제거하면 데이터베이스의 기록이 모두 지워지고, Vercel을
  거쳐 만든 데이터베이스는 다른 Neon 계정으로 옮길 수 없습니다(Neon 문서).

## 13. 다 됐는지 확인하는 방법

- `just check`가 통과합니다.
- 실서비스에서 새 탭으로 서비스를 열면 데이터베이스에 한 줄이 생기고, 새로 고침으로는
  늘지 않습니다. 같은 탭을 30분 넘게 가려 두었다가 다시 보면 한 줄이 더 생깁니다
  (시험에서는 시계를 가짜로 바꿔 확인합니다).
- `/stats`를 비밀번호 없이 열면 로그인 창이 뜨고, 틀린 비밀번호로는 들어가지 못합니다.
  Go 서버의 `/api/v1/stats`를 비밀값 헤더 없이 부르면 401입니다.
- `/stats`에서 일·주·월 단추를 누르면 그래프와 표가 그 단위로 바뀌고, 표의 숫자가
  데이터베이스에서 직접 센 값과 같습니다.
- `/stats`에 들어갔던 브라우저로 서비스를 다시 열어도 줄이 늘지 않습니다.
- 데이터베이스 연결 주소를 빼고 서버를 켜도 기존 조회(주변 음식점·장소 검색)는 그대로
  됩니다.
- 시작 화면 문장과 10절의 문서들이 고쳐져 있고, "저장소가 없"이라는 옛 표현이 사실과
  어긋난 채 남아 있지 않습니다.
