# 검색엔진과 링크 공유를 위한 기본 정비 — 설계 문서

## 1. 한 문단 요약

지금 이 서비스는 검색엔진과 메신저에 자신을 소개하는 정보가 제목과 설명 한 문장뿐입니다.
이번 변경은 화면을 하나도 늘리지 않고, 이미 있는 시작 화면을 검색엔진이 정확하게 읽고
카카오톡 등에 링크를 붙였을 때 미리보기가 제대로 나타나도록 정비합니다. 그리고 Google과
네이버에 사이트를 등록하여, 사람들이 실제로 어떤 검색어로 들어오는지 확인할 수 있게 합니다.

## 2. 왜 필요한가

운영자의 목표는 검색을 통한 유입을 크게 늘리는 것입니다. 그런데 검색 유입을 크게 늘리려면
검색어에 답하는 페이지가 여러 개 필요하고, 그런 페이지를 검색엔진만을 위해 만드는 것은
불필요하다고 운영자가 판단했습니다. 그래서 다음 기준을 세웠습니다.

> 검색엔진이 없더라도 사용자에게 쓸모가 있는 것만 만든다.

이번 작업은 이 기준을 통과하는 가장 작은 범위입니다. 어떤 방향으로 나아가든 반드시 필요한
토대이고, 다음 판단(페이지나 기능을 추가할지)을 추측이 아니라 실제 검색어 자료로 내릴 수
있게 해 줍니다.

## 3. 목표와 목표가 아닌 것

**목표**

- 검색엔진이 `/robots.txt`와 `/sitemap.xml`을 받아 갈 수 있고, 시작 화면(`/`)에 대표 주소가
  지정되어 있습니다.
- 카카오톡·SNS에 서비스 링크를 붙이면 제목, 설명, 그림이 있는 미리보기가 나타납니다.
- Google Search Console과 네이버 서치어드바이저에 사이트가 등록되어, 유입 검색어 통계를
  볼 수 있습니다.
- 서비스의 정식 주소가 한 곳(환경변수 하나)에서만 정해집니다. 나중에 자체 도메인을 구입하면
  그 값 하나만 바꾸면 됩니다.

**목표가 아닌 것**

- 음식 종류별·지역별 안내 페이지를 새로 만드는 것. 등록 후 몇 주 동안 쌓인 검색어 자료를
  확인한 뒤에 별도로 판단합니다.
- 결과 화면에 공유 버튼을 두는 것. 화면을 변경하는 별도의 기능입니다.
- 자체 도메인을 구입하는 것. 지금의 `https://random-choice-gamma.vercel.app`으로 시작합니다.
- 검색 광고, 블로그 소개 글 작성.

**이렇게 되면 실패입니다**

- 기존 화면(시작, 위치 검색, 후보 고르기, 결과, 기록)의 모습이나 동작이 달라지는 것.
- 운영자용 통계 화면(`/stats`)이 검색 결과에 노출되는 것.
- 미리보기 그림이나 설명에 후기·사용자 수처럼 실제로 없는 증거를 넣는 것
  (`PRODUCT.md`의 "Evidence on Hand").
- 정식 주소가 여러 파일에 따로 적혀서, 주소를 바꿀 때 일부만 바뀌는 것.

## 4. 확인된 사실과 확인되지 않은 것

**확인된 사실** (2026-11-21, 저장소와 설치된 Next.js 문서에서 확인)

- `web/app/layout.tsx`의 `metadata`에는 `title`과 `description`만 있습니다.
- `web/app/stats/page.tsx`는 이미 검색 제외(`robots: { index: false, follow: false }`)로
  표시되어 있고, 비밀번호로 보호됩니다.
- `robots.txt`, `sitemap.xml`, 공유 미리보기 그림, 대표 주소 지정, 검색엔진 소유 확인은
  어디에도 없습니다.
- 이 프로젝트의 Next.js는 `app/robots.ts`, `app/sitemap.ts`, `app/opengraph-image.png`
  파일 규칙과 `metadata`의 `metadataBase`·`verification` 항목을 지원합니다
  (`web/node_modules/next/dist/docs/01-app/03-api-reference/` 아래의 `robots.md`,
  `sitemap.md`, `opengraph-image.md`, `generate-metadata.md`).
- 홈 화면 아이콘은 `web/assets/`의 SVG 원본을 `web/scripts/make-icons.mjs`로 PNG로 바꿔
  저장소에 함께 올리는 방식으로 관리되고 있습니다.

- 시작 화면의 문구는 서버가 처음 내려 주는 HTML에 들어 있습니다. 정식 주소를 `curl`로 받아
  태그를 떼어 보면 서비스 이름, 안내 문장, 버튼 이름 셋이 그대로 나옵니다. 검색엔진이 읽을
  글이 이미 있으므로 이 부분은 고칠 것이 없습니다.
- 정식 주소(`https://random-choice-gamma.vercel.app`)의 응답에는 검색 제외 헤더
  (`X-Robots-Tag`)가 없어서 검색엔진이 수집할 수 있습니다(`curl -I`로 확인).
- 미리보기 배포는 Vercel이 검색 제외 헤더를 스스로 붙입니다
  (https://vercel.com/docs/deployments/environments 의 자주 묻는 질문). 그래서
  `robots.txt`에서 미리보기를 따로 막지 않습니다.

**확인되지 않은 것**

- 네이버 소유 확인 태그의 정확한 이름. `naver-site-verification`으로 알고 있으나, 운영자가
  네이버 서치어드바이저에서 코드를 발급받을 때 그 화면에 적힌 이름과 견주어 봅니다.

## 5. 검토한 방법과 고른 방법

1. **Next.js의 파일 규칙을 그대로 사용 (고른 방법).** 홈 화면 추가용 `web/app/manifest.ts`가
   이미 같은 방식이라 기존 코드와 형식이 일치하고, 추가 설치가 없습니다.
2. `web/public/`에 `robots.txt`·`sitemap.xml`을 직접 작성. 주소가 파일마다 따로 적혀서,
   주소를 바꿀 때 고칠 곳이 늘어납니다.
3. SEO 전용 라이브러리 추가. Next.js가 이미 제공하는 기능과 중복됩니다.

범위에 대해서는 세 가지를 검토했고, 운영자가 첫째를 골랐습니다.

1. **기본 정비 + 공유 미리보기 + 검색엔진 등록 (고른 범위).**
2. 위에 더해 음식 종류 열여덟 가지마다 소개 페이지를 추가. 검색엔진만을 위한 페이지라는
   이유로 제외했습니다.
3. 위에 더해 지역별 페이지를 추가. 카카오가 조회 결과의 저장을 금지하므로 가게 목록을 담을
   수 없고, 지명만 다른 같은 내용의 페이지가 됩니다.

## 6. 무엇을 만드는가

### 6-1. 정식 주소를 정하는 환경변수 (운영자가 정함: 지금의 vercel.app 주소로 시작)

- 환경변수 `SITE_URL`을 새로 둡니다. Vercel의 `random-choice` 프로젝트 정식(Production)
  환경에 `https://random-choice-gamma.vercel.app`을 넣습니다.
- 아래의 모든 항목은 이 값 하나에서 주소를 얻습니다. 값을 읽는 코드는 한 곳에만 둡니다.
- 값이 없을 때의 동작은 `API_ORIGIN`과 같은 방식을 따릅니다(`web/next.config.ts`): 개발용
  주소로 동작하되, 정식 빌드에서는 경고를 출력합니다. *(작성자가 정한 사항)*

### 6-2. `web/app/layout.tsx`의 `metadata`에 추가할 항목

- `metadataBase`: `SITE_URL`.
- 대표 주소(`alternates.canonical`): `/`.
- 공유 미리보기(`openGraph`): 제목, 설명, 주소, 사이트 이름 `오늘은 뭐 먹지?`, 언어
  `ko_KR`, 종류 `website`. 제목과 설명은 지금의 문장을 그대로 사용합니다.
- 큰 그림 형태의 미리보기(`twitter.card: "summary_large_image"`).
- 소유 확인(`verification`): 환경변수 `GOOGLE_SITE_VERIFICATION`,
  `NAVER_SITE_VERIFICATION`의 값. 값이 없으면 태그를 출력하지 않습니다. *(작성자가 정한
  사항: 확인 코드를 코드에 직접 적지 않고 환경변수로 받습니다)*

### 6-3. `web/app/robots.ts`

- 모든 검색엔진에 전체 수집을 허용하되 `/api/`만 제외합니다.
- `/stats`는 여기에 적지 않습니다. 이유는 두 가지입니다.
  - `/stats`를 검색에서 지켜 주는 것은 비밀번호입니다. 비밀번호가 없는 요청은 화면 내용을
    받지 못하므로(`web/proxy.ts`가 401로 응답합니다) 검색엔진이 가져갈 내용이 없습니다.
    Google의 안내도 페이지를 검색에서 빼는 방법으로 `robots.txt`가 아니라 검색 제외 표시나
    비밀번호 보호를 들고 있습니다
    (https://developers.google.com/search/docs/crawling-indexing/robots/intro, 2026-11-21 확인).
  - `robots.txt`는 누구나 읽을 수 있는 파일이라, 여기에 적으면 운영자용 화면의 주소를
    공개하는 셈이 됩니다. 또한 Google은 `robots.txt`로 막은 주소라도 다른 곳에서 링크되면
    주소만 검색 결과에 나올 수 있다고 안내합니다(같은 문서).
- `sitemap` 주소를 함께 적습니다.

### 6-4. `web/app/sitemap.ts`

- 주소는 `/` 하나입니다.

### 6-5. 공유 미리보기 그림

- 크기는 가로 1200, 세로 630입니다.
- 화면 바탕과 같은 나무색(`#e8d6b4`) 위에 앱 아이콘과 서비스 이름 `오늘은 뭐 먹지?`를
  둡니다. 그 밖의 문구나 숫자는 넣지 않습니다. *(작성자가 정한 사항. 완성된 그림은 운영자가
  확인합니다)*
- 아이콘과 같은 방식으로 관리합니다: `web/assets/`에 원본을 두고
  `web/scripts/make-icons.mjs`가 `web/app/opengraph-image.png`를 만들며, 만들어진 PNG를
  저장소에 올립니다. 그림을 설명하는 글(`opengraph-image.alt.txt`)도 함께 둡니다.

### 6-6. 검색엔진 등록 (운영자가 직접 하는 일)

계정 로그인이 필요하므로 운영자가 합니다. README에 다음 순서를 안내합니다.

1. Google Search Console과 네이버 서치어드바이저에서 사이트 주소를 추가하고, "HTML 태그"
   방식의 확인 코드를 발급받습니다.
2. 두 코드를 Vercel의 환경변수(6-2)에 넣고 다시 배포합니다.
3. 두 곳에서 "확인"을 누르고, `sitemap.xml` 주소를 제출합니다.

### 6-7. 문서

- README의 환경변수 표에 `SITE_URL`, `GOOGLE_SITE_VERIFICATION`,
  `NAVER_SITE_VERIFICATION`을 추가하고, 6-6의 등록 순서와 "자체 도메인으로 옮길 때 할 일"
  (`SITE_URL` 변경, 옛 주소를 새 주소로 넘기는 설정, 두 검색엔진에 다시 등록)을 적습니다.

## 7. 다 되었는지 확인하는 방법

- `cd web && npm test`가 통과합니다. `robots.ts`와 `sitemap.ts`에는
  `web/app/manifest.test.ts`와 같은 형식의 시험을 둡니다.
- `SITE_URL`을 준 채 `next build && next start`로 띄운 뒤,
  - `curl -s localhost:3000/robots.txt`와 `/sitemap.xml`에 `SITE_URL`의 주소가 나옵니다.
  - `curl -s localhost:3000/`의 HTML에 `rel="canonical"`, `og:title`, `og:description`,
    `og:image`, `twitter:card`가 있습니다.
  - `curl -s localhost:3000/stats`(비밀번호 포함)의 HTML에 `noindex`가 그대로 있습니다.
- 배포한 뒤 카카오톡 대화방에 주소를 붙여 미리보기에 제목·설명·그림이 나타나는지 봅니다.
- 기존 다섯 화면의 모습이 바뀌지 않았습니다.

## 8. 만드는 사람에게 맡기는 것

- `SITE_URL`을 읽는 코드의 위치와 이름.
- 미리보기 그림의 글자를 어떻게 그릴지(원본 SVG에 글자를 윤곽선으로 넣을지 등)와 요소의
  배치.
- 시험의 세부 구성.

## 9. 이번 작업 뒤에 할 일

등록하고 2~4주가 지나면 두 검색엔진의 통계에서 유입 검색어를 확인합니다. 그 자료를 근거로,
2절의 기준을 통과하는 페이지나 기능(예: 결과 공유 버튼)을 추가할지 판단합니다.
