# 가게 페이지를 앱 안에서 열기 — 설계 문서

## 1. 한 문단 요약

지금은 결과 화면에서 가게 이름을 누르면 카카오 가게 페이지가 새 탭으로 열립니다.
평점을 보고 마음에 들지 않으면 탭을 닫고 이 서비스로 돌아와야 하고, 이 왕복이 가게마다
반복됩니다. 이번 변경은 가게 이름을 눌렀을 때 화면 아래에서 창이 올라와 그 안에 카카오
가게 페이지를 보여 주고, `닫기`를 누르면 보던 목록으로 곧바로 돌아오게 합니다.

## 2. 왜 필요한가

사용자가 직접 써 보고 말한 불편입니다: "식당을 선택하면 브라우저가 실행되는데, 맘에
안 들면 다시 서비스로 돌아오는 게 불편하다. 지도로 가서 평점을 보고 3 이하면 안 간다."

원하는 것은 지도가 아니라 **이 서비스를 떠나지 않고 평점을 확인하는 것**입니다. 카카오
로컬 API는 평점을 주지 않으므로, 평점이 적힌 카카오 가게 페이지 자체를 화면 안에
띄웁니다.

## 3. 목표와 목표가 아닌 것

**목표**

- 결과 화면에서 가게 이름을 누르면 이 서비스 화면 위에 창이 뜨고, 평점·후기 수가 스크롤
  없이 보입니다.
- 창을 닫으면 목록, 스크롤 위치, 이미 누른 `여기로 정했어요` 표시가 그대로입니다.
- 창을 닫은 뒤 다른 가게를 눌러도 카카오 조회(서버 호출)는 다시 일어나지 않습니다.

**목표가 아닌 것**

- 목록에 평점 숫자를 표시하거나 평점이 낮은 가게를 자동으로 빼는 것. 평점을 받을 공식
  경로가 없습니다.
- 핀이 찍힌 지도. 별도 기능으로 `docs/todo.md`에 남아 있습니다.
- 기록 화면의 가게 링크. 지금처럼 새 탭으로 엽니다(왕복이 반복되는 곳은 결과 화면입니다).

**이렇게 되면 실패입니다**

- 카카오 쪽 사정으로 창이 빈 화면이 되었을 때 가게 페이지로 갈 길이 사라지는 것.
- 창을 여닫는 동안 뽑아 둔 결과가 사라지는 것.

## 4. 확인된 사실과 확인되지 않은 것

2026-11-19에 버릴 실험 페이지를 만들어 휴대폰 크기(390×844) 크롬 계열 브라우저로
확인했습니다.

- `https://place.map.kakao.com/장소ID`는 다른 사이트의 `iframe` 안에서 정상적으로
  표시됩니다. 응답에 `X-Frame-Options`와 `Content-Security-Policy`가 없었습니다.
- 높이 85%짜리 창에서 가게 이름, 평점, 후기 수, 영업시간이 첫 화면에 들어옵니다.
- 창 안에서 카카오의 로그인 확인 요청이 400 오류를 내지만 표시는 정상입니다.

만든 뒤 같은 날 크롬 계열 브라우저에서 더 확인한 것:

- 창 안의 `출발`·`도착`은 새 탭으로 카카오맵 길찾기를 엽니다. `앱 열기`는 아무 일도 하지
  않습니다. 어느 것도 이 서비스 화면을 다른 주소로 보내지 않습니다(`iframe`의 `sandbox`로
  막았습니다).
- 창 안의 `메뉴`·`후기` 같은 탭은 브라우저 방문 기록을 한 칸씩 쌓습니다. 그래서 창이 열린 채
  뒤로 가기를 하면 그 탭들을 먼저 되짚은 뒤 창이 닫힙니다.

확인되지 않은 것:

- 아이폰 Safari와 카카오톡 안 브라우저에서의 표시.
- 카카오 약관이 이 표시 방식을 허용하는지. **사용자가 카카오에 문의하지 않고 만들기로
  정했습니다(2026-11-19).**
- 앞으로도 계속 표시될지. 카카오가 서버 설정을 바꾸면 창은 빈 화면이 됩니다.

## 5. 검토한 방법

| 방법 | 장단점 | 결정 |
|---|---|---|
| 아래에서 올라오는 창에 카카오 가게 페이지를 띄운다 | 서버, 열쇠 발급, 새 라이브러리가 필요 없다. 카카오가 막으면 빈 화면이 된다 | **선택** (사용자가 실험 페이지를 써 보고 정함) |
| 같은 탭에서 카카오로 갔다가 뒤로 가기 | 가장 단순하다. 그러나 뽑은 결과를 메모리에만 들고 있어 돌아오면 목록이 사라진다 | 제외 |
| 평점만 긁어 와 목록에 표시 | 왕복이 아예 없어진다. 그러나 공식 경로가 없고 조회 결과 가공을 금지한 약관에 걸릴 소지가 크다 | 제외 |
| 지도 라이브러리로 핀 표시 | 평점이 나오지 않아 이 불편을 풀지 못한다 | 제외 |

## 6. 동작

```
┌──────────────────────────┐
│ 돈까스·우동  (어두워짐)   │
│ ┌──────────────────────┐ │
│ │ 가게 이름  카카오에서 │ │ ← 머리줄: 가게 이름, 새 탭 링크, 닫기
│ │            열기 [닫기]│ │
│ ├──────────────────────┤ │
│ │ kakaomap             │ │
│ │ ★ 3.8  후기 120      │ │ ← 카카오 가게 페이지
│ │ 사진 · 메뉴 · 후기    │ │
│ └──────────────────────┘ │
└──────────────────────────┘
```

- **여는 법**: 결과 화면에서 가게 줄(지금 새 탭이 열리는 그 영역)을 누릅니다. 가게 페이지
  주소가 비어 온 가게는 지금처럼 링크가 아니므로 창도 없습니다.
- **닫는 법**: `닫기` 버튼, Esc 키, 창 바깥의 어두운 영역 누르기. 닫으면 포커스가 눌렀던
  가게 이름으로 돌아갑니다.
- **`카카오에서 열기`**: 머리줄에 항상 보이는 새 탭 링크입니다. 창이 빈 화면이 되는 경우의
  대비책입니다. 막혔는지를 코드로 알아낼 믿을 만한 방법이 없어, 감지하지 않고 링크를 늘
  둡니다. *(작성자가 정한 것)*
- **링크는 링크로 남깁니다**: 가게 이름은 계속 `href`가 있는 링크이고 보통의 누름만 가로채
  창을 엽니다. 그래야 새 탭으로 열기(가운데 버튼, 길게 누르기)가 그대로 됩니다.
  *(작성자가 정한 것)*
- **저장**: 새로 저장하는 것이 없습니다. 창에 넣는 주소는 이미 받아 둔 가게 페이지 주소
  그대로입니다.

## 7. 만드는 사람에게 맡기는 것

- 창의 구현 수단(브라우저 기본 `dialog` 등), 올라오는 움직임과 그 생략
  (`web/app/globals.css`는 움직임 줄이기 설정에서 `.rise`만 끄는 규칙을 갖고 있습니다),
  색·모서리·머리줄 모양. `DESIGN.md`의 기준을 따릅니다.
- 창을 `web/components/ResultScreen.tsx` 안에 둘지 새 파일로 뺄지.
- 4절의 확인되지 않은 것 중 `앱 열기`·`출발`·`도착` 버튼의 동작을 만들면서 눌러 보고,
  화면 전체가 카카오로 넘어가 결과를 잃는다면 `iframe`의 `sandbox` 속성으로 막을 수
  있는지 확인합니다.
- 시험: 화면 파일(`.tsx`)은 지금 시험이 닿지 않으므로(`web/vitest.config.mts`), 시험할
  규칙이 생기면 `web/lib/`에 둡니다.

## 8. 함께 고칠 문서

- `DESIGN.md`: 결과 화면의 가게 줄 설명에 창을 더합니다.
- `README.md`: 가게 이름을 눌렀을 때의 동작 설명이 있으면 고치고, 4절의 "카카오가 막으면
  빈 화면이 된다"는 한계를 적습니다.
- `PRODUCT.md`: 화면 수(다섯 개)는 그대로입니다. 창은 결과 화면의 일부입니다.
