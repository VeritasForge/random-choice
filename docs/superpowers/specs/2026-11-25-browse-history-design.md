# 본 것은 다시 안 보여 주고, 이전 묶음으로 돌아가기 — 설계 문서

## 1. 한 문단 요약

후보 화면의 `다시 뽑기`와 결과 화면의 `다른 가게 보기`는 지금 **바로 직전에 보인 넷만**
피합니다. 그래서 세 번째로 누를 때부터 이미 보고 넘긴 음식 종류나 가게가 다시 나옵니다.
이번 변경은 두 가지를 합니다. 첫째, 이번에 본 것은 **한 바퀴를 다 볼 때까지** 다시
보여 주지 않습니다. 둘째, 두 화면에 `이전` 버튼을 두어 지나간 넷 묶음으로 한 단계씩
돌아갈 수 있게 합니다. `이전`과 `다시 뽑기`(`다른 가게 보기`)는 책장을 앞뒤로 넘기는
한 쌍처럼 동작합니다.

## 2. 왜 필요한가

운영자가 직접 써 보고 말한 불편입니다: "이미 본 게 또 나와서 답답했다." 이미 마음에
안 든다고 넘긴 것을 또 보여 주면 결정이 늦어지고, 이 서비스의 원칙 2("결정하는 시간을
줄이는 요소가 장식보다 우선", `PRODUCT.md`)에 어긋납니다.

반대로 다시 안 보여 주기만 하면, "아까 지나친 국밥이 다시 보고 싶다"는 사람이 남은 것을
다 넘길 때까지 그것을 볼 수 없습니다. 그래서 운영자는 이전으로 돌아가는 방법도 함께
요구했습니다.

비슷한 서비스로 오늘메뉴(https://oneulmenu.com/)가 "121개를 한 바퀴 보기 전에는 같은
메뉴가 다시 나오지 않아요"라고 화면에 밝혀 두었습니다(`docs/todo.md` 1번).

## 3. 지금 어떻게 동작하나

### 후보 화면(음식 종류)

- 조회가 끝나면 `start()`가 `pickDistinct`로 종류 넷을 뽑습니다(`web/app/page.tsx`).
- `다시 뽑기`는 `reshuffle()`이 처리하며, `pickAvoiding(종류 전체, 4, 지금 보이는 넷)`을
  부릅니다(`web/lib/pick.ts`). 피하는 것은 지금 보이는 넷뿐입니다.

```
주변 종류 12개: A B C D E F G H I J K L
처음         A B C D
다시 뽑기 1  E F G H      ← A~D를 피함
다시 뽑기 2  A C I J      ← E~H만 피하므로 A·C가 다시 나올 수 있음
```

### 결과 화면(가게)

- 종류를 고르면 `choose()`가 그 종류의 가게 전부(`all`)에서 최근에 정한 곳을 뺀
  목록(`pool`)을 만들고, `pickPlaces`로 넷을 뽑습니다(`web/lib/places.ts`).
- `pickPlaces`는 가까운 순으로 세운 뒤 앞에서 `windowSize`곳(처음 8곳)만 놓고 그 안에서
  뽑습니다. 가까운 가게를 먼저 권하기 위해서입니다.
- `다른 가게 보기`는 `reshufflePlaces()`가 처리하며, 범위를 8곳 넓히고 지금 보이는 넷만
  피해서 뽑습니다. 그래서 가게도 세 번째부터 다시 나올 수 있습니다.
- 이 버튼은 `places.length < pool.length`일 때만 보입니다(`web/components/ResultScreen.tsx`).
  가게가 넷 이하인 종류에는 붙지 않습니다.

### 상태를 어디에 들고 있나

두 화면의 상태는 모두 `page.tsx`의 `view`(화면별로 갈래가 나뉜 상태 하나)에 있습니다.
결과 화면 갈래는 후보 화면으로 돌아갈 때를 위해 `candidates`와 조회 결과(`result`)를 함께
들고 다닙니다. 조회를 다시 하면 카카오를 최대 123번 더 부르기 때문입니다.

## 4. 목표와 목표가 아닌 것

**목표**

- 한 번의 조회 안에서, 이미 본 음식 종류는 주변 종류를 한 바퀴 다 볼 때까지 후보 화면에
  다시 나오지 않습니다.
- 한 종류를 고른 결과 화면 안에서, 이미 본 가게는 그 종류의 가게를 한 바퀴 다 볼 때까지
  다시 나오지 않습니다. 가까운 가게부터 권하는 지금 방식은 유지합니다.
- 두 화면 모두 `이전` 버튼으로 지나간 넷 묶음에 한 단계씩 돌아갈 수 있습니다. 돌아간 묶음은
  처음 보았을 때와 내용과 순서가 같습니다.
- `이전`으로 돌아간 뒤 `다시 뽑기`(`다른 가게 보기`)를 누르면, 이미 본 묶음을 순서대로 다시
  지나가고, 기록의 끝에 닿은 뒤부터 새 묶음을 뽑습니다.

**목표가 아닌 것**

- 기록을 브라우저에 저장하는 것. 화면을 새로 고치면 사라집니다.
- 주변 종류가 넷 이하일 때의 동작을 바꾸는 것. 지금처럼 `다시 뽑기`를 눌러도 같은 넷이
  나옵니다.
- 지나간 종류나 가게를 목록으로 늘어놓고 골라 가는 화면. 검토했지만 후보 화면이 복잡해져서
  택하지 않았습니다(6절).
- `못 고르겠어요, 정해 주세요`의 동작. 지금처럼 화면에 보이는 넷 중에서 고릅니다.

**이렇게 되면 실패입니다**

- `이전`으로 돌아갔는데 처음 보았을 때와 다른 묶음이 나오는 것. 사용자는 "아까 그것"을 찾으러
  돌아가는 것이므로, 내용이 바뀌면 이 버튼을 믿을 수 없게 됩니다.
- 결과 화면에 갔다가 `다른 종류 고르기`로 돌아왔을 때 후보 화면의 기록이 사라지는 것.
- 한 바퀴를 다 보기 전에 이미 본 것이 다시 나오는 것.
- 버튼이 나타났다 사라지면서 아래 버튼들이 밀려 잘못 누르게 되는 것.

## 5. 동작 규칙

### 5.1 넘겨 본 기록

두 화면은 같은 규칙을 따르는 "넘겨 본 기록"을 하나씩 가집니다. 기록에는 세 가지가
들어 있습니다.

- **본 묶음들**: 지금까지 보여 준 넷 묶음을 본 순서대로 담은 목록.
- **지금 위치**: 그중 몇 번째 묶음을 보고 있는지.
- **이번 바퀴에서 본 것**: 이번 바퀴에서 한 번이라도 보여 준 항목들.

할 수 있는 일은 두 가지입니다.

- **이전**: 지금 위치를 한 칸 앞으로 옮깁니다. 첫 묶음에서는 아무 일도 하지 않습니다.
- **다음**: 지금 위치가 기록의 끝이 아니면 한 칸 뒤로 옮겨 이미 본 묶음을 다시 보여 줍니다.
  끝이면 새 묶음을 뽑아 기록 끝에 붙이고 그리로 옮깁니다.

```
본 순서:  ① A B C D  →  ② E F G H  →  ③ I J K L      (지금 ③)
이전 → ②, 이전 → ①
다음 → ②, 다음 → ③, 다음 → ④ 새로 뽑음
```

### 5.2 새 묶음을 뽑는 규칙과 한 바퀴

- 새 묶음은 **이번 바퀴에서 아직 안 본 것**에서 넷을 뽑습니다.
- 안 본 것이 넷보다 적게 남았으면, 남은 것을 모두 넣고 빈자리는 이미 본 것으로 채웁니다.
  이때 지금 화면에 보이는 묶음과는 되도록 겹치지 않게 채웁니다.
- 이렇게 채운 묶음을 보여 주는 순간부터 **두 번째 바퀴**입니다. "이번 바퀴에서 본 것"은
  이 묶음의 항목만 남기고 비웁니다. 그래야 두 번째 바퀴에서도 방금 본 것이 곧바로 다시
  나오지 않습니다.
- 안 본 것이 하나도 없으면(바퀴가 딱 맞게 끝났으면) "이번 바퀴에서 본 것"을 비우고, 지금
  보이는 묶음과 되도록 겹치지 않게 넷을 뽑습니다.

```
주변 13종류: ① A B C D → ② E F G H → ③ I J K L → ④ M + (A~L 중 셋) → 두 번째 바퀴
```

- 본 묶음 목록은 바퀴가 바뀌어도 지우지 않습니다. `이전`으로 첫 바퀴의 묶음까지 돌아갈 수
  있습니다.
- 항목이 같은지는 지금처럼 **객체 참조**로 견줍니다. 종류는 `distinctById`가 받은 객체를
  그대로 돌려주는 계약(`web/lib/cuisines.ts`)에, 가게는 `pool` 배열을 다시 만들지 않는
  계약(`web/lib/places.ts`)에 기댑니다. 가게를 식별자로 견주지 않는 이유는
  `places.ts`에 적혀 있습니다(식별자가 빈 가게가 있습니다).

### 5.3 두 화면의 차이

| | 후보 화면 (음식 종류) | 결과 화면 (가게) |
|---|---|---|
| 뽑는 바탕 | 조회 결과의 종류 전체 | 이 종류의 `pool` 중 가까운 순 범위 안 |
| 범위 | 없음 | 처음 8곳, **새 묶음을 뽑을 때마다** 8곳씩 넓힘. 이미 본 묶음을 다시 지나갈 때는 넓히지 않음 |
| 뽑은 뒤 정렬 | 없음(뽑힌 순서) | 가까운 순(지금과 같음) |
| 기록이 시작될 때 | 조회가 끝나 후보 화면이 처음 뜰 때 | 종류를 골라 결과 화면이 뜰 때 |
| 기록이 지워질 때 | `바꾸기`로 새 조회를 하거나 `처음부터 다시`를 누를 때 | 다른 종류(또는 같은 종류)를 다시 고를 때, `다시 넣기`·`다시 켜기`로 `pool`이 바뀔 때 |
| `다른 종류 고르기`로 돌아올 때 | 떠날 때 보던 묶음과 기록이 그대로 | 해당 없음 |

가게의 범위 규칙에서 "안 본 것"은 **범위 안에서 안 본 것**입니다. 범위가 8곳씩 넓어지고
한 번에 넷씩 보므로, 범위가 `pool` 전체에 닿기 전에는 범위 안에 안 본 가게가 늘 넷 이상
남습니다. 범위가 `pool` 전체에 닿은 뒤에는 5.2의 한 바퀴 규칙을 그대로 따릅니다.
두 번째 바퀴에서도 범위를 다시 8곳으로 줄이지 않고 `pool` 전체로 둡니다(설계 작성자 판단).
지금 코드도 범위를 넓히기만 하고 줄이지 않습니다.

### 5.4 버튼

```
후보 화면                               결과 화면
[카드 넷]                               [가게 넷]
[ 이전 후보 ] [ 다시 뽑기 ]             [ 이전 가게 ] [ 다른 가게 보기 ]
[ 못 고르겠어요, 정해 주세요 ]          [ 다른 종류 고르기 ]
                                        [ 처음부터 다시 ]
```

- `이전 후보`·`이전 가게`는 첫 묶음을 보고 있을 때 **흐리게 두고 누를 수 없게** 합니다.
  숨기지 않는 이유는 4절의 마지막 실패 조건 때문입니다. `DESIGN.md`의 Disabled 규칙대로
  `disabled` 속성이 아니라 `aria-disabled="true"`와 클릭 무시로 처리합니다. `disabled`를 쓰면
  `이전`을 누르다 첫 묶음에 닿는 순간 그 버튼에 있던 키보드 포커스가 사라집니다.
- `이전 가게`는 `다른 가게 보기`가 붙는 경우에만 붙입니다. 가게가 넷 이하인 종류에는 둘 다
  없습니다(지금과 같습니다).
- 주변 종류가 넷 이하일 때 `다시 뽑기`는 지금처럼 보입니다. 이때 `이전 후보`도 함께 두되,
  묶음 내용은 같습니다. 이 경우의 버튼 처리는 만드는 사람에게 맡깁니다(8절).
- 화면 낭독기 사용자를 위해 지금 `다시 뽑기`·`다른 가게 보기`가 쓰는 알림 영역
  (`role="status"`)이 `이전`을 눌렀을 때도 바뀐 목록을 읽게 합니다. 지금 구조에서는 목록이
  바뀌면 저절로 읽히므로 따로 할 일은 없을 것입니다.

## 6. 만드는 방법

### 고른 방법: 넘겨 본 기록을 순수 함수 모듈로 만들어 두 화면이 함께 쓴다

`web/lib/` 아래에 새 모듈을 하나 둡니다. 이 모듈은 5.1·5.2의 규칙만 압니다.

- 기록은 바꿀 수 없는 값(새 기록을 돌려주는 방식)으로 다룹니다. `view` 안에 그대로 담기
  위해서입니다.
- 무작위 함수는 지금 `pick.ts`처럼 밖에서 받습니다(`Rng`). 시험에서 정해진 값을 넣기
  위해서입니다.
- "새 묶음을 뽑는 방법"만 화면마다 다릅니다(5.3). 가게 쪽의 범위 넓히기와 거리순 정렬을
  모듈 안에 넣을지, 부르는 쪽에서 넘겨줄지는 만드는 사람이 정합니다.

`page.tsx`의 `view`에서는 후보 화면 갈래와 결과 화면 갈래의 `candidates`를 후보 기록으로,
결과 화면 갈래의 `places`·`windowSize`를 가게 기록으로 바꾸거나 함께 둡니다. 결과 화면
갈래는 후보 기록을 들고 다녀야 `다른 종류 고르기`로 돌아왔을 때 기록이 이어집니다.

### 검토했지만 택하지 않은 방법

| 방법 | 택하지 않은 이유 |
|---|---|
| `page.tsx`에 화면마다 기록 상태와 로직을 따로 넣기 | 같은 규칙을 두 번 구현하게 되어 한쪽만 고치는 실수가 생깁니다 |
| 각 화면 컴포넌트 안에서 React hook으로 기록 들고 있기 | 결과 화면에 갔다가 돌아오면 후보 화면 컴포넌트가 새로 그려져 기록이 사라집니다 |

### 화면 쪽에서 검토했지만 택하지 않은 모양

| 모양 | 택하지 않은 이유 |
|---|---|
| 지나친 종류를 카드 아래에 작게 늘어놓고 눌러서 바로 가기 | "아까 그것"을 한 번에 고를 수 있지만, 후보 화면에 정보가 늘어나 "넷 중에 고른다"는 단순함이 흐려집니다 |
| `이전`으로 돌아간 뒤 `다시 뽑기`를 누르면 늘 새로 뽑기 | 새 묶음에서 `이전`을 누르면 돌아간 자리가 아니라 기록 끝의 묶음으로 가는 등, 순서가 헷갈립니다. 지나간 묶음을 다시 찾기도 어려워집니다 |

## 7. 운영자가 정한 것

- 이미 본 종류와 가게는 한 바퀴를 다 볼 때까지 다시 보여 주지 않는다.
- 두 화면 모두 `이전` 버튼으로 넷 묶음을 한 단계씩 되돌린다.
- `이전`과 `다시 뽑기`(`다른 가게 보기`)는 앞뒤로 넘기는 한 쌍이다.
- 다음 일곱 가지 세부 동작(2026-11-25 확인): 첫 묶음에서 `이전`은 흐리게 둔다 / 후보 기록은
  한 번의 조회 동안 유지되고 `다른 종류 고르기`로 돌아오면 보던 묶음으로 돌아온다 / 가게 기록은
  종류를 고를 때마다 새로 시작한다 / 가게가 넷 이하인 종류에는 두 버튼 모두 붙이지 않는다 /
  가게도 한 바퀴를 다 돌면 남은 것부터 보여 주고 두 번째 바퀴로 넘어간다 / `정해 주세요`는
  화면에 보이는 넷 중에서 고른다 / 기록은 새로 고치면 사라진다.
- 버튼 배치(2026-11-25 확인): `이전 후보`·`다시 뽑기`(결과 화면은 `이전 가게`·`다른 가게 보기`)를
  한 줄에 반 폭씩 나란히 두고, `정해 주세요`는 지금처럼 가로 가득 둔다. 높이 48px과 간격
  12px는 유지한다. `DESIGN.md`의 "후보 화면의 두 버튼" 항목은 `다시 뽑기`와 `정해 주세요`를 둘 다
  가로 가득 두기로 한 예전 결정을 적고 있으므로, 이번 결정에 맞게 함께 고친다. 예전 결정의
  핵심(`정해 주세요`를 낮추지 않고, 버튼 사이 간격을 충분히 둔다)은 그대로 지켜진다.

## 8. 만드는 사람에게 맡기는 것

아래는 대화에서 정하지 않았고, 정하는 방식에 따라 사용자가 보는 결과가 크게 달라지지 않는
것들입니다. 제(설계 작성자) 판단을 적어 두지만 더 나은 방법이 있으면 바꿔도 됩니다.

- **`다시 넣기`·`다시 켜기`로 `pool`이 바뀔 때 가게 기록을 지운다**(설계 작성자 판단).
  지금도 이때 범위를 처음으로 되돌리고 새로 뽑습니다(`toggleAvoid()`). 바뀐 `pool`에는
  이전 묶음의 가게가 없을 수 있어 기록을 이어 가면 규칙이 어긋납니다.
- **주변 종류가 넷 이하일 때** `이전 후보`·`다시 뽑기`를 어떻게 보일지. 지금 `다시 뽑기`가
  그대로 보이므로, 같은 넷만 계속 쌓이는 기록이 생기지 않게만 하면 됩니다.
- 모듈의 이름, 기록의 정확한 자료 구조, `view` 갈래의 필드 이름.
- 버튼 두 개를 한 줄에 나란히 둘 때의 세부 스타일. 높이 48px, 간격 12px, 반 폭은 7절에서
  정했고, 나머지는 `DESIGN.md`의 기존 버튼 규칙을 따릅니다.
- `README.md`의 화면 그림(③·④)과 설명에 새 버튼과 동작을 반영하는 것.

## 9. 시험

- 새 모듈은 `vitest`로 규칙을 시험합니다. 적어도 다음을 확인합니다.
  - 한 바퀴 안에서 같은 항목이 두 번 나오지 않는다(항목 수가 넷의 배수일 때와 아닐 때 모두).
  - 바퀴가 넘어갈 때 남은 것이 모두 들어가고, 빈자리가 지금 묶음과 겹치지 않는다.
  - `이전`을 여러 번 누른 뒤 `다음`을 누르면 이미 본 묶음이 같은 내용·같은 순서로 다시 나오고,
    끝에 닿은 뒤에만 새로 뽑는다.
  - 첫 묶음에서 `이전`은 아무것도 바꾸지 않는다.
  - 항목이 넷 이하일 때 깨지지 않는다.
  - 가게 쪽: 이미 본 묶음을 다시 지나갈 때 범위가 넓어지지 않는다.
